# 初始化、卸载与撤销

## 操作顺序

1. 读 `finance_ledger_read(mode=summary)`，确认根、`uninit`、已有节点和余额范围。用 `finance_query_transactions` 查范围内的具体 `tx_id`；初始化用 `initialized=0`，卸载用已初始化项并读当前归属。若用户指定选区，保留其明确范围，不能把空数组改成全部。
2. `finance_ledger_apply(op=init, tx_ids=[...])`。只有明确说全部尚未初始化交易才用 `all_uninitialized=true`，引擎在实际执行事务里解析，返回真实 `tx_count`。
   - 按已有节点放置：`target`；新建一个节点承接：`new_node`（`name`、可选 `parent`）。
   - 按平台分类：`style=platform`；用户未指定组织方式时这是默认预设，不是默认全量。
   - 一次放多个目标或一起建组/分裂：`plan`，顺序是 `nodes` → `place` → `splits` → `groups`；`meta` 可以设置标题和备注。ID 以执行回执为准。用 `plan={}` 明确放根。
3. 卸载用 `op=uninstall` 和明确的 `tx_ids`。如果用户说卸载某节点下的所有交易，沿子项和组成员读全页、收集主交易 id；一个主交易与其镜像只算一个 id。卸载会连带撤掉镜像；组若不足两人会解散。读回节点与候选核对。
4. 撤销/重做先读 `summary.status.history`。`undo` 针对最新 `applied`，`redo` 针对最早 `undone`。若用户说「撤刚才那步」，用上一份回执的 `expected_seq`，确认它确实是栈顶。若只是拆掉旧组而组创建并非最近操作，用 `dissolve_group` 操作指定组，别撤用户其它改动。

## 为什么

- **账本归属不是凭证。** 初始化只是让已导入的交易进入树，卸载只注销 V2 归属和人工字段；原始流水可重用。要保留原样（备注/组/分裂）时用撤销，而非重新初始化猜原状。
- **类型与范围决定操作。** 范围投影只影响怎么看；移动组员可能搬整组，卸载单笔仅卸该交易但可能解散组。别让所选对象的联动变成未要求的修改。
- **一次把交易放对。** 自定义 init 比先全量初始化再挪一遍更直接，也使用户可以一次撤回这次操作。先核对实效再汇报，不把本次创建节点数误当交易笔数。
