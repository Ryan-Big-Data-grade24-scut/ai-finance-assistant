# 个人财务助手

> **一句话**：现有记账工具给你的账是**它定义的账**，不是**你要的账**。我们做的是中间这一层。

---

## 一、这个项目分两层

```
┌──────────────────────────────────────────┐
│  机械部分（确定性，不含任何智能判断）        │
│  ① 跨平台账单导入 → 统一数据格式            │
│  ② 对统一数据格式生成图表                   │
│  ③ MCP 接入，可操控上述功能                │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│  智能部分（处理"用户要什么"这件事）          │
│  ① 了解用户做这个账单的目的                 │
│  ② 跟用户统一支出的口径                     │
│  ③ 根据目的制作账单                         │
│  ④ 帮助用户做决策                           │
└──────────────────────────────────────────┘
```

**一条红线**：智能部分**不许自己写 SQL**。它把用户的意图编译成可执行条件，交给机械部分执行。

## 四、三条不可让步的原则

1. **未解释的钱必须显式挂在账单上。** 竞品的做法是藏起来，我们选择摊开。
2. **禁止"月均"，必须逐月并排。** 2 月春节、8 月暑假会被平均抹平。
3. **边界要落在代码上，不能只写在文档里。** 改只读字段必须报错，且可现场演示。
