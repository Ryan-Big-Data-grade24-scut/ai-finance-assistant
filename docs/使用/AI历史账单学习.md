# AI 历史账单学习

## 目的

对已经导入到 `star-live` 账本的历史交易进行一次性 AI 分类分析。此功能不重新上传账单、不重新导入交易，也不修改 `transactions_raw` 原始记录。

## 使用前提

1. 在「AI 设置」中保存模型服务商、Base URL、模型名称和 API Key。
2. 勾选「允许将必要交易字段发送到所配置的模型接口」。
3. 先通过「测试连接」确认模型服务可用。

## 工作流程

1. 打开「历史账单学习」。
2. 查看历史交易总数、已确认交易数和人工分类保护数。
3. 点击「开始分析历史账单」。后端创建持久化任务并在后台执行整批分析。
4. 页面自动轮询任务状态。分析完成后展示分类体系、逐笔建议、置信度和判断理由。
5. AI 优先匹配当前账本已有分类。新增分类必须由用户勾选批准。
6. 页面默认选择置信度达到当前阈值、且目标分类已经存在的建议。用户可以逐笔调整选择。
7. 用户可勾选「记住」将商户或商品规则保存到现有 `ai_classification_rules`。
8. 点击确认后，后端通过 `classification.service` 创建分类草案并调用 Ledger Engine 确认归类。

## 保护规则

- 已有 `ai_classification_reviews` 确认记录的交易不会重复分析。
- `tx_overrides` 中存在人工大类/小类覆盖的交易不会被本次 AI 重写。
- 退款、全额退款、内部转账和退款证据冲突等特殊交易由既有分类规则排除。
- 历史批量学习不会因为模型置信度高或设置了自动规则而静默修改旧账。所有历史重分类必须由用户在页面明确选择并确认。
- 原始交易只读；分类变更通过 Ledger Engine 保存，可追溯并可按现有分类提案流程撤销。
- 长期规则只在用户主动勾选「记住」并确认交易后保存。

## API

- `GET /api/ai/history/status`：历史账单学习概况。
- `POST /api/ai/history/analyze`：创建历史分析任务。
- `GET /api/ai/history/{session_id}`：读取任务状态和分析结果。
- `POST /api/ai/history/{session_id}/commit`：提交用户选择的历史分类。

## 当前范围

本阶段完成历史交易分析、分类审核、长期规则保存和 Ledger 落账。独立的全局 AI 对话助手（跨页面对话、历史对话管理、财务问答）作为下一阶段开发，不与本次历史学习任务混在一起。
