# 一、`backend/schemas.py`

## 已有的是什么

我们写了 7 个报告函数、2 个导入器、3 个 CRUD 模块。它们全是普通 Python 函数，各自有各自的入参、各自返回各自的 dict。

## 存在什么问题没解决

### 问题 1：前端不知道你返回什么形状

函数返回 `{"total": ..., "count": ...}`。前端写 `res.data.total`。

万一路径拼错，或者哪天你把 key 从 `total` 改成 `sum`——**前端一片空白，没有任何报错**，因为返回的 dict 里根本没有 `total` 这个键。

### 问题 2：AI 不知道你有哪些工具 ⚠️ 最要命

这是最严重的一条。

Claude / 豆包这类 MCP 客户端，连接时会读取工具的 schema 来决定「这个工具怎么调、参数叫什么名字」。

**schema 靠什么生成？靠 Pydantic 模型。**

你不写模型 → FastAPI 生成不出 OpenAPI → MCP Server 生成不出工具定义 → **AI 根本不知道你有哪些工具、每个工具要传什么参数。**

我们的第一轮目标「MCP 操控以上全部」直接落空。

### 问题 3：脏参数打到最后才崩

AI 传了个 `type=expendise`（拼错了）。

- 没有校验：SQL 查不到数据 → 返回空 → **AI 以为这个月没花钱，给用户一个错误答案**
- 有校验：入口直接返回 `type 必须是 expense 或 income`

第二种更糟：**错误答案比报错危险得多。**

## 提出的设计

```python
Period = Literal['week', 'month', 'year']
TxType = Literal['expense', 'income']

class ReportReq(BaseModel):
    type:   TxType
    period: Period
    value:  str = Field(pattern=r'^\d{4}(-W\d{2}|-\d{2})?$')

class SummaryResp(BaseModel):
    total: float = Field(description="本期合计金额（元，两位小数）")
    prev:  float = Field(description="上期合计（元）")
    delta: float = Field(description="total - prev，可为负")
    rate:  float | None = Field(
        description="环比百分比。17.2 表示 +17.2%。prev=0 时为 null"
    )
    count: int = Field(description="交易笔数，不是天数")
```

**一次解决三个问题：**

| 解决什么 | 怎么解决 |
|---|---|
| AI 不知道有哪些接口 | Pydantic 模型 → 自动生成 MCP 工具 schema |
| 前端不知道返回什么形状 | 同一份模型 → `/docs` 里能看到字段说明 |
| 脏参数打到最后才崩 | `Literal` 在入口就拦下 |

### 关键：`Field(description=...)` 不是注释

这些 description 会**自动进 OpenAPI**，队友在 Swagger 或 Postman 里就能看到。

因为代码里表达不了「17.2 表示 17.2% 而不是 0.172」这种语义，description 是唯一能让队友不猜的地方。**该写就写，别省。**

### 还有一个隐藏作用

```python
class OverrideIn(BaseModel):
    model_config = ConfigDict(extra="forbid")
    manual_category: str | None = None
    manual_subcat: str | None = None
    is_exempt: bool = False
    funding: str = "自有"
    note: str | None = None
```

**这里【没有】任何原始字段名**——`amount`、`tx_time`、`direction` 一个都没有。

MCP 客户端靠这个模型生成工具 schema，**AI 从协议层面就传不进来**。这是三道防线里的第一道。

### 附：样例数据也放在这里

```python
EXAMPLE_SUMMARY = {
    "total": 1900.00, "prev": 2800.00,
    "delta": -900.00, "rate": -32.1, "count": 82,
}
```

队友对着这个看，比看文档快。所有数字都是**验算过的一致值**。

# 二、`backend/overrides.py`

## 已有的是什么

前端要能改分类，AI 也要能改分类。最自然的做法是在两个地方各写一遍。

## 存在什么问题没解决

那句校验——**「原始字段一个都不许碰，碰到就 403」**——就得写两遍：

```
main.py 的路由处理函数          自己写一遍校验  ✅
backend/mcp/server.py 的工具函数 自己写一遍校验  ❌ 忘了
```

结果就是：**前端那条路拦住了，AI 那条路没拦住。**

AI 通过 MCP 直接把一笔支出的金额从 32 改成 3.2，账本从此不可信。

而这恰恰是我们对外宣称的**核心卖点**。

> **卖点不能靠自觉守，必须靠结构守。**

## 提出的设计

把写入逻辑收成一个文件，让两个入口都穿过它：

```
前端 PATCH /api/tx/1/override ─┐
                               ├─→ overrides.set_override()
MCP  tool: set_override ────────┘
              ↑
        唯一的校验点（只有这一份代码）
```

### 三道防线

| # | 防线 | 在哪 | 作用 |
|---|---|---|---|
| ① | **协议层** | `schemas.OverrideIn` 没有原始字段名 | MCP / HTTP 的 schema 从这里派生，AI 传不进来 |
| ② | **运行时** | `FORBIDDEN_FIELDS` 黑名单 | 万一 Pydantic 配宽了，这里再挡一次 |
| ③ | **结构层** | 本模块不存在写原始层的代码路径 | **前两条是约定，这条是物理事实** |

第 ③ 条最硬。即使前两条被绕过，代码里也没有那条路径。

### 顺带解决的问题：可追溯

```sql
updated_by TEXT   -- 'ui' / 'mcp'
```

每次写入记录来源。三个月后你查一眼就知道「这笔是人改的还是 AI 改的」。

### 还有撤销

```python
def clear_override(tx_id): ...   # DELETE FROM tx_overrides WHERE tx_id = ?
```

只删修正那一行，原始层永远不动。这是「反悔」的唯一方式。

# 三、`backend/main.py`

## 已有的是什么

5 个报告函数、2 个导入器、3 个 CRUD 模块，全都写好了。它们是普通 Python 函数——**定义了不等于会执行。**

## 存在什么问题没解决

**谁来调用它们？**

必须有个人接收到「用户要看 9 月账单」这个信号，然后决定调 `get_summary`。这个「接信号 → 分发 → 返回」的动作没有人写。

## 提出的设计

```python
app = FastAPI(title="AI Finance Assistant", version="0.1.0")

@app.on_event("startup")
def _startup(): db.init_db()

# 导入
POST /api/import/preview | commit | GET history
# 报告（全部只读 GET）
GET /api/report/summary | calendar | trend | by-category
                 | by-method | income-rank | transactions
# 写修正
GET   /api/tx/{id}
PATCH /api/tx/{id}/override
DELETE /api/tx/{id}/override
```

### 唯一的硬性原则

> **`main.py` 里不出现任何业务逻辑。**
> 看到 `if month == '2026-09':` 就说明逻辑漏进来了，该挪走。

它只干四件杂事：

| 它做的 | 为什么不能放在别处 |
|---|---|
| 注册路由 | 需要集中管理一张 URL 表 |
| 启动时 `init_db()` | 只该执行一次 |
| CORS | 全局设置，跟业务无关 |
| 统一错误响应 | 否则每个路由都要写 try/except |

### 顺带把 403 翻译成招牌行为

```python
@app.exception_handler(RequestValidationError)
async def _validation(_req, exc):
    for err in exc.errors():
        field = str(err.get("loc", ())[-1])
        if field in FORBIDDEN_FIELDS:
            return _json_error(403, f"原始字段不可修改: {field}")
    return _json_error(400, exc.errors())
```

FastAPI 默认会返回 422。这里把「试图改原始字段」翻译成 403——因为**对 AI 和用户来说，这是个值得单独告知的事实，不是一个普通的校验错误。**
