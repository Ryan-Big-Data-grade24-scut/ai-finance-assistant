# 第二轮 · 引擎

> 代数（`记账代数.md`）的工程实现。
> 特点：**可逆** —— 任何层级的聚合关系都成立，缩小视图必然等于展开视图。

---

## 一、总特点：可逆

引擎的核心性质是**可逆**：**任意缩小视图，得到的数必然等于展开它。**

```
M₁ = Σ M₁ᵢ = Σ Σ M₁ᵢⱼ = ⋯
```

**任何节点，任何时刻，这条等式都成立。**

这不是一条要额外维护的性质，而是**树结构本身的推论**——只要：

1. 每笔交易 τ 恰好属于一个叶子
2. 每个内部节点的值 = 其子节点值的聚合

等式就自动成立。

**为什么这条性质是引擎的全部价值：**

用户改一笔、挪一笔、拆一笔，都是**局部的**操作。但由于可逆，**总账永远等于所有叶子的加总**——用户不需要"重算全表"，引擎也不需要。用户只管眼前的局部，账自己会平。

> **可逆是引擎能承受"前端乱造"的原因。**
> 前端再怎么拖，引擎都不会算错，因为总账不是存出来的，是**每次从叶子重新聚合出来的**。

### ⚠️ 一处边界

**分裂不守恒。** τ 拆成两条腿后，总账增加一笔镜像（`记账代数.md` §2.4）。

所以严格地说：

| | 可逆？ |
|---|---|
| 结构操作（建节点、挪交易、聚合） | ✅ 严格可逆 |
| 分裂 | ⚠️ 值不守恒，但**结构可逆**（可合回去） |

引擎要保证的是后者：**分裂后的结构能还原成分裂前的样子**，且还原后数值一致。这靠的是**记录操作日志**，而不是靠算术。

## 二、初始状态：M₀

引擎必须有初始状态，不可避免。

```
M₀ = Σ_{τ ∈ X} atom(τ)      所有交易以 +₁ 直接加总
```

**M₀ 是根节点**，op = ADD，直接持有全部交易的腿。

这正是 `记账代数.md` §3.5 说的**退化情形 = 平台预设账本**：

> 若整棵树只有一层（根 + 全部腿），且 op = ADD，这就是平台账单默认做的事。

所以：

> **M₀ 不是特例，它是引擎的起点，也是任何时刻"把树全collapse掉"的结果。**

这给了引擎一个性质：**任意时刻都能回到 M₀**，且能验证回得对不对。

⚠️ 但注意：**M₀ 不等于"正确账"**。它只是起点。用户看到的第一眼应该是一个**扁平的、平台口径的账**——和支付宝账单页长得一样。这是刻意的：**先让用户认出它，再让他改它。**

## 三、树

### 3.1 结构

```
节点 n := ( id, name, op, parent, children, legs )
                op ∈ { ADD, NET }

叶子：children = ∅，直接持有若干 τ 的腿
内部：children ≠ ∅，按 op 聚合子节点的值
根：  M₀
```

### 3.2 恒等式

任意节点：

```
Y_n = op_n ( ⨆_{c ∈ children(n)} Y_c )
```

沿根到叶任意路径可反复展开：

```
Y_n = op_n ( ⨆ op_{n_j} ( ⨆ … op_leaf ( ⨆ ℓ ) ) )
```

### 3.3 聚合只有两种 op

| op | 定义 | 含义 |
|---|---|---|
| `ADD` | `Y_n = ⨆ Y_c` | 各子项直接相加 |
| `NET` | `Y_n = net( ⨆ Y_c )` | 组内正负相抵后取净额 |

**没有第三种。** 代数 §3.3 已经论证过：凡是"不该进报表"的东西，都在腿生成阶段就处理掉了。

> ⚠️ **`NET` 的幂等性**（代数 I6）是引擎必须保证的性质：
> `net(net(X₁) + net(X₂)) = net(X₁ + X₂)`
> 这保证了 NET 节点在任意嵌套深度下结果一致——**否则"缩小视图等于展开视图"会在 NET 节点上崩掉**。

### 3.4 深度

**不设深度上限。** 树有多深，由用户决定。

引擎的正确性只靠 (C1)(C2) 和 §3.2 的恒等式——**与深度无关**。深度 1（只有根）、深度 2、深度 5，都是同样合法的树。

## 四、原子操作

引擎支持四类操作。**前三类是代数算子，第四类是结构操作。**

### 4.1 `+₁` / `+₂` —— 切换节点的 op

```
ADD ↔ NET
```

- `ADD`：子项直接相加
- `NET`：子项相抵后取净额

**为什么是"切换"而不是两个操作**：代数 §3.3 说 `op` 只有两种，且节点的值**只由 op 和子节点值决定**。所以它是一个**状态**，不是一个动作。

**可逆**：切回去就还原了。

> ⚠️ **顺序不可交换**：`NET` 之后再 `ADD` 回去，值不一定相同（净额化是有损的）。
> 这正是代数 I6 存在的原因——它保证**嵌套 NET 不会多吞**。

### 4.2 `split(τ)` —— 分裂一笔交易

```
τ ⟶ ℓ₁ +₁ ℓ₂,   ℓ₂ = mirror(ℓ₁)
```

一笔消耗外部额度的流动，拆成"一条去路 + 一条来源"。

**适用域**（代数 §2.4，**严格限定**）：

| τ 的性质 | 可分裂 |
|---|---|
| 消费、收入、普通转账 | ❌ |
| 自己的账户之间划转 | ❌ |
| 自己的池子之间搬运 | ❌ |
| **涉及外部额度**（额度归属方在自己名下之外） | ✅ |

**为什么范围必须限定**：分裂会凭空增加一笔镜像流入。对普通交易这么做毫无依据。

**引擎怎么判定"涉及外部额度"**：靠一个显式的额度来源配置（`funding` 那一层），不是靠金额或商户名猜。

**顺序铁律**（代数 §2.5）：**先查退款，再决定分裂。**

```
IF 有配对退款腿  →  1 条零腿
ELIF 涉及外部额度 →  2 条
ELSE              →  1 条
```

**可逆**：结构上可还原（把两条腿合回一条 τ），但**数值不还原**——因为分裂本身就不守恒。所以还原必须靠**操作日志**。

### 4.3 ⛔ 对 `+₂` 对象分裂 —— 不实现

**决定不实现。** 理由：

1. **没必要** —— 代数里没有为它下定义（`记账代数.md` 只定义了原子层的分裂）
2. **不直观** —— 用户要表达"先相抵、再拆分"，得同时理解两个方向的顺序，在 UI 上是**两个手势指向同一对象，含义相反**
3. **不常用** —— 真实场景里，需要"相抵后再拆"的极少

> **这条要记下来**：因为代数 §2.6 说"所有判断都在原子层完成"，而"对已聚合结果再分裂"是唯一的例外。**不实现它，等于把例外排除在系统外**——这是好事，但要写明。

### 4.4 建子节点

```
在父节点 M_* 下创建子节点 M_**
```

**语义**：把父节点的一部分划出来，给它一个名字和 op。

**实现上就是树的重挂**——原来直接挂在 `M_*` 下的若干 τ，改挂到新节点 `M_**` 下。

```
操作前:  M_* → [τ1, τ2, τ3]
操作后:  M_* → [M_**]
              M_** → [τ1, τ2, τ3]
```

**可逆**：把 `M_**` 的 τ 放回 `M_*`，删掉 `M_**`，值不变。

⚠️ **但值可能变** —— 如果 `M_*` 是 NET 而 `M_**` 是 ADD（或反过来），聚合方式变了，值会变。
**所以建节点必须显式声明新节点的 op**，且引擎要能说清"这次操作让总账变了多少"。

### 4.5 改交易归属

```
把 τ 从节点 A 移到节点 B
```

**语义**：改变某笔交易归到哪个口径下。

**这是 AI 分类插件唯一的写操作**（`01_AI分类插件.md` §4.1）。

**可逆**：移回去。**值不变**（除非 A、B 的 op 不同导致聚合方式变化——引擎要报出来）。

### 4.6 四个操作的可逆性一览

| 操作 | 结构可逆 | 数值可逆 | 备注 |
|---|---|---|---|
| `+₁ ↔ +₂`（切 op） | ✅ | ⚠️ 净额化有损 | |
| `split(τ)` | ✅ | ❌ 不守恒 | 靠日志还原 |
| 建子节点 | ✅ | ⚠️ 取决于 op | |
| 改归属 | ✅ | ⚠️ 取决于 op | |

> **所以引擎需要一份操作日志**——不为了审计好看，是为了**"还原"这个能力真的存在**。
> 快照是日志的一个特例。

## 五、引擎要守的东西

三条。第一条是代数给的，第二三条是引擎自己的。

### 5.1 腿的唯一归属与完备

```
(C1) ∀ ℓ ∈ 所有腿:  恰好一个节点 n 使 ℓ ∈ legs(n)
(C2) ⋃_n legs(n) = ⋃_τ legs(τ)
```

**没有孤儿、没有重复。** 每次操作后自动校验，不通过就拒绝。

### 5.2 总账恒等于叶子加总

```
Y_root = ⨆_{τ ∈ X} atom(τ) + （分裂产生的镜像）
```

**引擎每次聚合时顺手算一遍根值和叶子加总，比对。** 不等就是引擎有 bug。

> 这一条是"前端乱造不会算出错账"的**技术兑现**：总账不是存出来的，是每次从叶子重算的。**它不可能和叶子不一致**，除非引擎自己错了。

### 5.3 可缩可放

```
任意节点 n:  Y_n = op_n ( ⨆ Y_c )
```

**缩小任意子树，得到的钱必须等于它原本的值。**

这一条在 UI 上就是：**点任何节点展开/收起，数字不变。**

## 六、引擎的对外接口

引擎是前端和插件的共同底座。**两边走同一套接口、同一套校验。**

```
前端 ──┐
       ├──→ 引擎 ──→ 落账
插件 ──┘
```

大致形状：

| | 操作 |
|---|---|
| **读** | 取整棵树 / 取某个子树 / 取某笔交易的详情 |
| **写** | 切 op / 分裂 / 建节点 / 改归属 |
| **查** | 当前状态：多少笔已归位、多少笔待归、不变量是否通过 |
| **还原** | 按快照或日志回到某个历史状态 |

> **写操作全部经过引擎这一个口子。** 谁发起的都一样，校验一样。
> 这是 `00_设计思路.md` §6.2 那句话的实现：**"后端不会出任何错误"是引擎的职责。**
