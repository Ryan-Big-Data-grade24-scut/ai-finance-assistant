# 第二轮 · 前端

> 星图与列表，同一棵树的两个投影。
> 用户在界面上的每个手势，对应引擎的一个操作。

---

## 一、三种状态

界面不是从零开始，是**从 M₀ 出发，经过可选的 AI 归类，最后是用户自己的形态**：

```
M₀（平台口径，扁平）        AI 归类态（可选）           用户态
所有交易 +₁ 加总      →    交易被归到若干节点    →    用户任意改造
                          （插件干的）
```

**为什么 AI 归类态要单列一层：**

- 它是**可逆的**。AI 归类的本质是若干次「改交易归属」操作，引擎记着日志 → 整体撤销即可
- 用户可能**不认可**它 → 要能退回 M₀ 重来
- 它是**中间态**，不是终点

> ⭐ **所以「可逆」不只是树内部的性质，它在状态层面也成立**：
> M₀ ⇄ AI 归类态 ⇄ 用户态，三者之间任意跳转，账不会算错。

## 二、两种视图

| | 星图 | 列表 |
|---|---|---|
| 结构 | 根在中心，向外发散 | 按时间/按节点平铺 |
| 适合 | 看结构、改结构 | 逐笔核对、检索 |
| 布局 | 确定性径向分层 | 表格 |

**两者是同一棵树的两个投影，共享同一份状态。** 选中、展开、聚焦都必须联动。

### 2.1 星图

```
              L4 组（一次 AA 聚餐）
                    │
     ┌──────────────┼──────────────┐
   正餐            零食          地铁
  ┌─┴─┐          ┌─┴─┐        ┌─┴─┐
  τ   τ          τ   τ        τ   τ
```

- **离中心距离 = 深度**
- **扇形角度 = 占总账的比例**
- **节点上标记 = ADD / NET**
- **叶子 = 一笔交易**

### 2.2 列表

每行一笔交易（或一个节点），显示：时间 / 对象 / 标题 / 金额 / 所属节点 / (e,i)。

## 三、手势 → 引擎操作

**这是本文的核心。** 每个手势严格对应 `02_引擎.md` 的一个操作，不多不少。

| 用户手势 | 引擎操作 | 备注 |
|---|---|---|
| **把 τ₁ 拖到 τ₂ 上**（同一父节点） | 建子节点，op = **NET**，含 {τ₁, τ₂} | ← **这就是「+₂」** |
| 把 τ 拖到某个节点 M 上 | **改交易归属**：τ 从原节点挪进 M | |
| 把 τ 从组里拖出 | 改交易归属：挪回父节点 | |
| 把节点 M₁ 拖到 M₂ 上（同一父节点） | 改归属：M₁ 整棵子树挪进 M₂ | |
| 点节点详情 → 「新建分组」 | 建子节点（空），op 可选 | 命名后拖成员进去 |
| 点节点详情 → 切换标记 | **切 op**：ADD ↔ NET | |
| 点 τ 详情 → 「拆分」 | **split(τ)** | 仅外部额度的 τ 可用 |
| 撤销 / 重做 | 引擎操作日志回退 | |

### 3.1 ⭐ 为什么「+₂」是拖到另一笔上面

界面默认所有节点是 ADD。**净额化是一个有损操作**（正负相抵，抹掉中间态），所以它必须是一个**刻意的手势**，不能是默认行为。

「把 τ₁ 拖到 τ₂ 上」正好传达这个语义：

> **一笔压到另一笔上 = 两者相抵**

典型场景就是第一轮那个 AA 聚餐：

```
支出 125（我垫付）   ← 把「收回 112.40」拖到它上面
        ↓
NET 组 = (0, 12.60)   ← 净额就是我自己的那份
```

**前提「属于同一个 M」** 是必要的：跨节点拖动涉及重挂和 op 变化，语义完全不同，不该用同一个手势。

### 3.2 建空分组 vs 拖出 NET 组

两条路径，意图不同：

| 想要 | 用 |
|---|---|
| 一个 ADD 的组（正餐、零食） | 「新建分组」→ 命名 → 拖成员进去 |
| 两个数相抵 | 直接拖一个到另一个上面 |

**分开是因为**：ADD 组是「归类」，NET 组是「抵消」。混在一个手势里用户会不知道自己干了什么。

### 3.3 前端不算钱

> **界面上的每一个数字都来自引擎。** 前端只做展示和手势识别，不做任何金额聚合。

拖动时为了让手感即时，可以先本地算个预估值，但**最终值以引擎返回为准**。

## 四、详情面板

### 4.1 点交易 τ

显示：
- 交易对象（counterparty）
- 标题 / 商品说明（item）
- 时间
- 金额
- **(e, i) 向量** ← 引擎返回的这条腿的实际值
- 平台原始分类、备注、支付方式
- 当前所在节点（含 op）

**支持的操作**：
- **拆分**（`split`）—— 仅当引擎判定它涉及外部额度时可用，否则置灰并说明原因
- 移动到别的节点
- 标记 / 备注

### 4.2 点节点 M_*

显示：
- 名称
- **op（ADD / NET）**，可切换
- 值 (e, i)
- 子节点数、直接持有多少笔交易
- 占比

**支持的操作**：
- **新建分组**
- 切换 ADD / NET
- 解散（子节点回流父节点）

> ⚠️ **点节点和点交易的区别在星图里必须明显**：节点是环，交易是点。点错了改的是不同的东西。

## 五、检索与定位

### 5.1 检索

搜什么：交易对象、标题、备注、金额、分类名。

命中后：
- **列表视图**：过滤 / 高亮，命中的行高亮
- **星图视图**：命中的叶子高亮，**但树不重排**（重排会破坏位置记忆）

### 5.2 ⭐ 定位：把视野缩到命中处

点一条检索结果 → **相机移到那个节点，把它放到中心**，其余部分淡出。

- 星图：镜头推近到该子树，它成为新的中心
- 列表：滚动到该行并高亮

**这条能力很重要**：星图的节点可能很深、离中心很远，**不推近根本找不到**。

> 「缩放到那个位置」同时也是**聚焦模式**的入口——聚焦后在这个子树里的操作，作用域更清晰。

## 六、可逆在界面上的落地

### 6.1 撤销 / 重做

引擎有操作日志，界面就有标准的撤销栈。

**每个操作都必须可撤销**，包括：切 op、拖动、建组、拆分、AI 归类（整批撤销）。

### 6.2 状态条

```
┌────────────────────────────────────────────────────┐
│ 2026-09 · 口径「日常」 · AI 归类后 · 1,058 笔       │
│ 支出 4,588.94   收入 4,728.00   净 +139.06         │
│ 不变量 6/6 通过 ✓   未归位 0 笔                    │
│                             [回到 M₀] [撤销 3 步]  │
└────────────────────────────────────────────────────┘
```

三个数是引擎的，状态条不重算。

**「回到 M₀」** 是最直接的「可逆」体现：一键退回最初的样子。

### 6.3 乐观更新 + 引擎校验

```
用户拖动 → 前端立刻动 → 引擎执行 → 校验 → 返回权威树
                                    │
                            被拒 → 回滚 + 说清原因
```

**被拒的表现**：不是弹个错误框，而是——**节点抖一下 + 一句人话**。

> 例：「这两笔不在同一个分组下，不能直接相抵。」
> 而不是：「INVALID_PARENT_SCOPE」
