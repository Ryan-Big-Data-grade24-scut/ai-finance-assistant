## 1. 迭代记录

### 1.1 第一版

12 张表（`ledger_book` / `ledger_book_tx` / `ledger_node` / `ledger_leg` / `ledger_net_group` /
`ledger_net_group_member` / `ledger_refund_pair` / `ledger_split` / `ledger_split_tx` / `ledger_history` …），
7 个类（`Tx` `Leg` `Node` `NetGroup` `Split` `RefundPair` `Policy`）。

### 1.2 第一轮砍（13 条）

| # | 砍掉 | 理由 |
|---|---|---|
| C1 | 腿表 `ledger_leg` | `[t]` 是交易的函数（N4）；归属只需「一笔交易一个父节点」 |
| C2 | 成员集冻结表 `ledger_book_tx` | 成员 = 有归属行的交易；无行 = 在根 → 基础账本**零写入**（N2） |
| C3 | `ledger_node.op` | M 恒 +1（N18） |
| C4 | `ledger_node.kind` | `parent_id IS NULL` 就是根（N13） |
| C5 | `ledger_refund_pair` | 原文 N1–N21 没有退款 |
| C6 | `ledger_split`（映射表） | 分裂副本是树上的另一种叶子，`Tx.role='mirror'` 即可（N19） |
| C7 | t′ 的 `node_id` | 「t′ 自动继承 t 的路径」→ 位置派生，不存（N19） |
| C8 | t′ 的独立 id | 用 `src_tx_id` 当键，「只能分裂一次」由主键保证（N19） |
| C9 | 组成员表 | 标记位挂在 `ledger_placement.net_group_id`（N7） |
| C10 | `ledger_history` | 撤销原文没提；本版不做 |
| C11 | 「外部收入节点」 | t′ 是普通叶子（N19） |
| C12 | 分裂适用域限制 | 「分裂实现起来很简单」→ 无条件可分裂（N19） |
| C13 | 账本的 `date_from/date_to` | 时间范围是**读时参数**（N14） |

### 1.3 第二轮砍（多账本 → 一个数据库一本账）

| # | 砍掉 | 理由 |
|---|---|---|
| C14 | `ledger_book` 整张表 | 「用户搞一本账已经很麻烦了」。**一个数据库就是一本账**，不同阶段用不同数据库文件 |
| C15 | 所有表上的 `book_id` | C14 的直接后果。删掉后**跨账污染在结构上不可能发生**，外键全部退化成简单外键 |
| C16 | 类 `Book` | 数据库已经是账本了，装配出来的根 `Node` 就是账本本身，不需要再包一层 |

`book_id` 砍掉后，节点 id 必须**全局唯一**（UUID），因为不再有「书内唯一」这个概念了。

### 1.4 第三轮：Q1–Q5 的落地（本轮）

用户对上一版遗留问题的答复：**Q1 不能放宽**；**Q2 组成员可以是 t′**；**Q3 组内净额按交集算**；
**Q4 所有操作可逆**；**Q5 先建好数据结构跑通，再考虑移植正式**。

| # | 决定 | 落地方式 | 代价 / 理由 |
|---|---|---|---|
| D1 | 组的位置**显式存** | `ledger_net_group.node_id NOT NULL` | 位置不再靠「从成员推导」。推导在三个操作下会失效（成员移走 / 单个成员被移动 / 新建节点只包住部分成员），而且**失效后不可恢复** |
| D2 | +2 组**必须同父**，不放宽（Q1） | 建组 / 加员时逐笔比对 `node_id`，不同就拒绝并报出各自所在的分组 | 与 N18 一致；放宽要先定「净额挂到哪一层」 |
| D3 | 组成员**可以是 t′**（Q2） | `ledger_placement` 加 `role` 列，主键 `(tx_id, role)`；`primary` 与 `mirror` 同一张表 | C7「t′ 位置完全派生」必须放弃 —— 派生位置的交易没法当组成员。**代价见 §2.5** |
| D4 | 组内净额按**成员 ∩ 范围**算（Q3） | `read_scope` 过滤组成员后再算 ν | 与 N9 一致 |
| D5 | 所有操作**可逆**（Q4） | 底层「原语」+ 操作日志；撤销 = 执行逆原语序列 | 不需要快照表：快照恢复不了「组里有几笔、分别是谁」这种结构 |

**新砍的（第三轮）**：

| # | 砍掉 | 理由 |
|---|---|---|
| C17 | `ledger_net_group_member` 成员表 | 成员 = `ledger_placement.net_group_id` 的反查；「一笔交易至多属于一个组」由一列保证 |
| C18 | `ledger_history` 快照表 | D5：原语日志能逐字段还原，快照不能 |
| C19 | t′ 的独立 id | 沿用 `src_tx_id` + `role='mirror'` 联合定位 |

### 1.5 收敛后

## 2. 数据表

### 2.0 一句话总览

```
transactions_raw（既有，事实，不动）
        │  tx_id
        ▼
ledger_placement ──── 一笔账本交易（原始/镜像）的一个归属 + 可选净额组标记
   (tx_id, role)      ▲                    ▲
        │          ledger_node          ledger_net_group
        │          （树，parent_id IS NULL 即根）  （组的位置也存一份）
        │
ledger_split_tx（分裂事实：src_tx_id 为键）      ledger_op_log（撤销/重做的原语日志）
```

**隔离单元是数据库文件**：一个 DB 文件 = 一张原始表 + 一棵树 + 一套关系。

### 2.1 `ledger_node` —— 树节点 M

```sql
CREATE TABLE ledger_node (
    id        TEXT PRIMARY KEY,                       -- UUID，全局唯一
    parent_id TEXT REFERENCES ledger_node(id) ON DELETE RESTRICT,
    name      TEXT NOT NULL
);
CREATE INDEX idx_ledger_node_parent ON ledger_node(parent_id);

-- 至多一个根（N13：不会出现分散的树）
CREATE UNIQUE INDEX idx_ledger_node_one_root
    ON ledger_node((1)) WHERE parent_id IS NULL;
```

- 每本账（= 当前 DB）**有且只有一个** `parent_id IS NULL` 的根（N13）。
- 没有 `op` 列：M 恒为 +1 聚合（C3 / N18）。
- 没有 `book_id`：数据库就是账本（C14/C15）。

### 2.2 `ledger_placement` —— 归属 + 净额组标记

```sql
CREATE TABLE ledger_placement (
    tx_id        INTEGER NOT NULL REFERENCES transactions_raw(id) ON DELETE CASCADE,
    role         TEXT    NOT NULL CHECK (role IN ('primary', 'mirror')),
    node_id      TEXT    NOT NULL REFERENCES ledger_node(id) ON DELETE RESTRICT,
    net_group_id TEXT    REFERENCES ledger_net_group(id) ON DELETE RESTRICT,
    PRIMARY KEY (tx_id, role)
);
CREATE INDEX idx_ledger_placement_node  ON ledger_placement(node_id);
CREATE INDEX idx_ledger_placement_group ON ledger_placement(net_group_id);
```

**一张表承担三件事**：

1. **归属**（N1 的树状关系）：一笔账本交易**恰好一个父节点**。
2. **标记**（N7）：`net_group_id` 非空 = 这笔交易被某个 +2 组标记了。
3. **区分原始交易与分裂副本**（D3 / Q2）：`role` 让 t′ 和原始交易共用一张表，
   于是「t′ 也能当组成员」不需要另开成员表。

**默认规则（无行 = 在根）**：

> 交易 t 的父节点 = 若有 `placement(t)` 则取 `node_id`，否则是根节点 M_r。

于是：

- 基础账本（无树、无组）**一行都不写**（N2 ✓）。
- 把交易移回根 → 删掉这一行。
- 属于某个 +2 组的交易即使在根，也必须有这一行（用来挂标记）。

### 2.3 `ledger_net_group` —— +2 关系集合

```sql
CREATE TABLE ledger_net_group (
    id      TEXT PRIMARY KEY,                          -- UUID
    name    TEXT,
    node_id TEXT NOT NULL REFERENCES ledger_node(id) ON DELETE RESTRICT
);
```

**「独立的 id + 不定长成员数组」的落地**（N6）：

```
组的成员数组 = SELECT tx_id, role FROM ledger_placement WHERE net_group_id = :gid
```

成员不重复存一份，由 `net_group_id` 反查得到。好处：

- 「标记」与「归属」在同一行，天然不会走散；
- 「一笔交易至多属于一个组」由**一列**保证，不需要额外唯一索引；
- 增删成员 = 改一行的 `net_group_id`（N10）。

**`node_id` 是 D1 加的**：组的位置**显式存下来**，不再靠「任一成员的 `node_id`」推导。
理由：推导的前提是「成员永远同父」，而这个前提会被三个操作打破，且打破之后**位置无法恢复**。
显式存下来之后：

- 位置不会因为某个成员被单独挪走而丢失；
- 漂移可以被**检测**（读时校验：成员 `node_id` 必须等于 `group.node_id`）和**修复**；
- 「同父」从「推导出来的前提」变成「可校验的不变量」（D2）。

### 2.4 `ledger_split_tx` —— 分裂事实

```sql
CREATE TABLE ledger_split_tx (
    src_tx_id INTEGER PRIMARY KEY
              REFERENCES transactions_raw(id) ON DELETE CASCADE
);
```

一行 = 这笔交易**被分裂过**（t′ 存在）。它只回答「有没有 t′」这一个问题：

| 属性 | 来自 |
|---|---|
| t′ 存在吗 | `ledger_split_tx` 的这一行（主键保证「只能分裂一次」，N19） |
| t′ 的位置 | `ledger_placement(tx_id, 'mirror').node_id`（**显式**，见 §2.5） |
| t′ 的 IE 向量 | `μ(atom(t))`，算出来的（N19） |
| t′ 属于哪个 +2 组 | `ledger_placement(tx_id,'mirror').net_group_id`（默认 NULL = 不继承，N19） |

### 2.5 D3 的代价：t′ 的位置从「派生」改成「显式」

C7（第一轮）砍掉 t′ 的位置，理由是「t′ 自动继承 t 的路径」。Q2 答复「可以是 t′」之后，
这个砍法站不住：**位置靠派生出来的交易，没法挂标记，也就没法当组成员**。

改成显式之后：

- 分裂那一刻，t′ 的位置 = t 当时的位置（**继承路径**，N19 仍然成立）；
- 之后 t′ 是独立叶子，可以被单独移动、可以加入组（Q2）；
- 「不继承 +2 关系」= 分裂时 `net_group_id` 写 NULL。

「t′ 永远跟着 t 走」这个更强的性质**不再成立** —— 这是 D3 明确付出的代价，
记在这里以免将来被当成 bug。

### 2.6 `ledger_op_log` —— 撤销 / 重做（D5）

```sql
CREATE TABLE ledger_op_log (
    seq        INTEGER PRIMARY KEY AUTOINCREMENT,
    op_json    TEXT NOT NULL,      -- {"name": "create_node", "prims": [...]}
    undo_json  TEXT NOT NULL,      -- 逆原语序列
    state      TEXT NOT NULL DEFAULT 'applied'
               CHECK (state IN ('applied','undone','discarded')),
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**三个 state**：

| state | 含义 |
|---|---|
| `applied` | 已生效 |
| `undone` | 已撤销、可以重做 |
| `discarded` | 撤销之后又做了别的事 → 这个操作作废，**不能再重做** |

`discarded` 这条规则是必须的：没有它，「撤销 → 改点别的 → 重做」会把旧操作**复活**，
账本状态和操作历史对不上（原型第一版就踩过，已修）。

**为什么不存快照**：快照能还原「每个节点挂在哪」，但还原不了「这个 +2 组里有哪几笔、分别是谁」。
原语日志两样都能还原 —— 撤销就是把原语反着执行一遍（D5：撤销用的是**同一操作集里的其它操作**）。

## 3. 类

### 3.0 表 ↔ 类

| 类 | 表 | 行的含义 |
|---|---|---|
| `Tx` | `transactions_raw` + `ledger_split_tx` + `ledger_placement` | 一笔账本交易（原始或镜像） |
| `Node` | `ledger_node` | 一个 M 节点 |
| `NetGroup` | `ledger_net_group` + `ledger_placement` | 一个 +2 关系集合 |
| `Scope` | —— （不是表） | 读时作用域 |
| `TxRef` | —— （不是表） | 对一笔交易的引用：`(tx_id, role)`，`'tx:1'` / `'txm:3'` 这种写法解析成它 |

**类不是表的镜像，而是「读出来的一棵树」。**
数据库存的是**扁平行**，类是把这些行**装配成树**之后的产物，装配发生在 `read_ledger()` 里：

```
数据库（扁平行）  ──read_ledger() 装配──▶  Node 树  ──read_scope() 投影──▶  读出树
   ledger_node                Node（子项是 Tx / Node / NetGroup）
   ledger_placement
   ledger_net_group
   ledger_split_tx
```

这就是「数据库里怎么跟类结合」的答案：**表是数据，类是装配结果，函数是装配与投影。**

### 3.1 `Tx` —— 一笔交易

```python
@dataclass
class Tx:
    id: int                 # transactions_raw.id（mirror 与它的源同 id）
    role: str               # 'primary' | 'mirror'
    amount: int             # 分
    direction: int          # +1 收入 / -1 支出 / 0 中性
    tx_time: str
    date: str

    def value(self) -> tuple[int, int]:
        """⟦τ⟧ = atom(τ)（N4）。mirror 取 primary 的镜像。"""
        e, i = atom(self.amount, self.direction)
        return (i, e) if self.role == 'mirror' else (e, i)
```

**向量的分量约定（必须写死，否则全仓口径会打架）**：

> `(e, i)` = (**支出**, **收入**)。支出 30.00 → `(3000, 0)`；收入 50.00 → `(0, 5000)`。

IE 向量**算出来的，不是存着的**（N3）。

### 3.2 `NetGroup` —— +2 组

```python
@dataclass
class NetGroup:
    id: str
    name: str
    node_id: str                    # 组的位置（D1：显式存）
    members: list[Tx]
    value: tuple[int, int] | None   # ν(⊕ 范围内成员)
```

**ν 的语义（容易想歪，记牢）**：先 +1 相加，再两个分量同时减去较小者。
所以**只有组里同时有收入和支出时才会发生抵消**；同向的两笔原样相加。

```
ν(支出30, 收入50) = (0, 20)    → 净收入 20
ν(支出20, 支出25) = (45, 0)    → 原样相加
ν(支出100, 收入100) = (0, 0)   → 完全抵消
```

性质：`ν(ν(x)) = ν(x)` —— 任意嵌套幂等，组套组不会多扣一次。

### 3.3 `Node` —— 树节点 M

```python
@dataclass
class Node:
    id: str
    parent_id: str | None
    name: str
    children: list['Tx | Node | NetGroup'] = field(default_factory=list)
    value: tuple[int, int] | None = None
```

**装配规则（必须遵守，否则重复计数）**：

> 被某个 +2 组标记的交易，**只出现在组里面**，不再作为节点的直接子项出现。

于是 `Node.value()` 可以无条件对所有子项 +1，正好对应 `[t1, [t2,t3,t4]+2, t5, …]+1`（N5/N8）。

### 3.4 `Scope` —— 作用域

```python
@dataclass(frozen=True)
class Scope:
    tx_ids: frozenset[int]
```

- 时间范围 → `scope_by_date(conn, date_from, date_to)`（N14）。
- 分类筛选 → 取子树的 tx 集合再喂进来。
- **只有这一个筛选入口**，时间与分类不各搞一套。

## 4. 函数

### 4.1 纯函数（无 IO）

| 函数 | 定义 | N |
|---|---|---|
| `atom(amount, direction) -> (e, i)` | 支出 `(a,0)`；收入 `(0,a)`；中性记支出 | N4 |
| `mirror(v) -> (e, i)` | 两个分量互换 —— t′ 的向量「刚好反过来」 | N19 |
| `plus1(values) -> (e, i)` | 分量相加 | N5 |
| `net(values) -> (e, i)` | 先相加，再把两个分量同时减去较小者 | N8 |
| `top(items) -> items` | 折叠：去掉「被集合里其它元素覆盖」的项 | N16 / N17 |
| `lca(node_ids) -> node_id` | 最近公共祖先 | N16 |

`top()` 的定义（N16 的「自动排除掉 t2 t3」）：

> 若 x 是 y 的严格后代（y 是节点、x 在 y 子树内），则 x 被 y 覆盖，`top` 里不留 x。

### 4.2 读

| 函数 | 作用 |
|---|---|
| `read_ledger(conn) -> Node` | 读扁平行 → 装配成根 `Node`（子项含 `Tx` / `Node` / `NetGroup`）；顺带校验组的不变量 |
| `scope_by_date(conn, date_from, date_to) -> Scope` | 时间范围 → `tx_ids`（N14） |
| `read_scope(root, scope) -> Node` | 在装配好的树上投影，返回读出树（每个节点带 `e, i`） |
| `to_json(node) -> dict` | 读出树 → JSON（将来 HTTP / MCP 的返回值形状，见 §5） |
| `render(node) -> str` | 读出树 → 人看的文本（调试用） |

`read_scope` 三步（N14）：

```
1. 取 scope 内的交易 X
2. 投影：保留「X 中某笔交易的祖先」这些节点 → 最小覆盖树；
   根永远保留；空范围时只有根，值 (0,0)
3. 逐节点算值：Node.value()（子项为组时用 NetGroup.value()）
```

> N11「去年生效的分类今年不出现」= 第 2 步：没有范围内后代的节点**整个不出现**（不是显示成 0）。

**读时硬校验**（D1 的兜底）：组的成员数 < 2、或成员的 `node_id` 与 `group.node_id` 不一致 → **报错**，
而不是静默地把它们当成普通交易加进去。

### 4.3 写

| 函数 | 前置条件 | N |
|---|---|---|
| `create_node(conn, name, items) -> node_id` | 至少一项；被选中项求 LCA，新节点挂在 LCA 下；`top()` 折叠后各项改挂到新节点 | N16 |
| `move(conn, items, target_node_id)` | target 不是任何被移动项的后代（不成环）；移动的是 `top(item_ids)`，各元素**保持独立不合并** | N17 |
| `dissolve_node(conn, node_id)` | 非根；子节点上移到父节点 | 现有 UI |
| `create_net_group(conn, items, name) -> group_id` | ≥2 笔；**必须同父**（D2/Q1）；每笔当前不属于任何组 | N10 / N18 |
| `add_group_member(conn, group_id, item)` | 新成员与组内现有成员**同父**；不属于其它组 | N10 |
| `remove_group_member(conn, group_id, item)` | 成员在组内；减到 <2 个成员时**组自动解散**（R3） | N10 |
| `split_tx(conn, tx_id)` | tx 未被分裂过 | N19 |
| `unsplit_tx(conn, tx_id)` | tx 已分裂；只删 t′，t 原样保留 | N19 |
| `undo(conn)` / `redo(conn)` | 撤销 / 重做最后一次操作（D5） | Q4 |

#### 选择解释 + 批量写（引擎层用到，2026-11-19 补）

| 函数 | 作用 |
|---|---|
| `fold_selection(conn, items)` | **最简**：丢掉「被已选 M 覆盖」的后代、被已选组覆盖的成员；返回 `(nodes, groups, txs)` |
| `fold_for_join(conn, items)` | 最简 + 必须全是交易；有 M / +2 → `JOIN_REQUIRES_TX` |
| `expand_selection(conn, items)` | **最繁**：选中的 M 展开整棵子树（节点 / 组 / 交易），选中的 +2 展开全部成员 |
| `dissolve(conn, node_ids, group_ids)` | 批量解散（深先删），一次撤销；根 → `CANNOT_DISSOLVE_ROOT`；空选择 → `NOTHING_TO_DISSOLVE` |
| `add_group_members(conn, group_id, txs)` | 批量加员（去重）；非交易 → `NOT_A_TX`、已在别的组 → `ALREADY_GROUPED`、跨父 → `SAME_PARENT_REQUIRED`；`add_group_member` 是单入口包装 |
| `update_group(conn, group_id, name, note)` | 组改名 / 改备注；无变化 → `NO_EFFECT` |
| `split_txs(conn, tx_ids)` / `unsplit_txs(conn, tx_ids)` | 批量分裂 / 取消分裂；unsplit 时成员 <2 的组按 R3 自动解散 |

#### 三条硬规则

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R1 同父** | +2 组成员必须同父，跨父直接拒绝并报出各自所在的分组 | N18；Q1「不能放宽」 |
| **R2 整组不可分割** | 移动 / 建组碰到组里的一笔 → **自动带上整组** | 组的位置 = 成员的共同父节点；拆开就不成组了 |
| **R3 不足 2 人自动解散** | 组减到只剩 1 个成员时，组解散、剩下的成员回到普通交易 | 组只剩 1 个成员时 ν 没有意义，且会留下孤儿组 |

#### 撤销的实现：原语 + 日志（D5）

底层是**原语**（直接改表的最小动作），每个原语都能算出自己的逆：

```
node_create ↔ node_delete          tx_place ↔ tx_unplace
node_parent ↔ node_parent(旧值)    group_create ↔ group_delete
group_node  ↔ group_node(旧值)    split_add ↔ split_remove
```

一次用户操作 = 一串原语；**撤销 = 把这串原语反着执行**；重做 = 再正着执行一遍。

**重做栈的语义**（已验证）：

- 撤销总是撤「最后一个 applied 的操作」；
- 重做总是做「最后一个被撤销的操作」（即 undone 里 seq 最小的那个 —— 撤销是倒着来的，最小的 seq 最后被撤）；
- **做了新操作 = 重做栈清空**（那些 undone 的日志被标成 `discarded`）。

用户层的每个操作也都在这个操作集里闭合：

```
create_node   ↔ move(回去) + dissolve_node
move          ↔ move(回原父)
dissolve_node ↔ create_node + move(回去)
建组/加员/减员 ↔ 减员/加员/解散组
split_tx      ↔ unsplit_tx
```

#### 其它要点

- **`move` 的唯一移动集合**（N17）：不管一个 t、多个 t、一个 M、多个 M、还是 M-t 组合，
  移动的都是 `top(item_ids)` —— 一个去重后、保持原有结构的集合。
  `[M_1, t1, t2]` 里的三个元素仍独立，只是同时换了父节点，**不合并**。
- **分组的同父检查**（N18）：成员分散在不同 M 下时**拒绝**并报出各自的父节点。
  要跨 M 就先建分组把成员收拢到同一父下。

## 10. 已实现的数据结构（当前真相）

位置：`backend/ledger2/schema.sql`。相对 §2 的原型设计有六处变化：

1. **表名全部加 `ledger2_` 前缀**，与 V1 的 `ledger_*` 完全不相干；
2. **新增 `ledger2_meta`**：键值元数据（目前只有 `schema_version`）；
3. **新增 `ledger2_op_log`**：原型的撤销靠内存栈，成品改成「正向原语序列 + 逆序列」落库
   （Q4：所有操作可逆，撤销用的是同一操作集里的其它操作）；
4. **归属与人工字段合并成一张 `ledger2_tx`**：`node_id` / `net_group_id` 和
   `initialized` / `title` / `note` / `category_path` 是同一行；镜像行只管归属，人工字段恒为空；
5. **交易不在 V2 的表里**：事实来自既有的 `transactions_raw` / `tx_overrides` / `tx_deletions`，
   V2 只读，不复制；
6. **「无归属行 = 在默认父节点」作废**：已初始化的交易、以及分裂出的副本 t′，**必须**有一行
   `ledger2_tx`；没有行 = 没初始化 = 读不出来。分类节点也不再是读时虚拟的，
   而是平台分类预设建出来的**真节点**（`cat:` 只是命名约定）。

于是整个 V2 共 **6 张表**：`ledger2_meta` / `ledger2_node` / `ledger2_net_group` / `ledger2_tx` /
`ledger2_split_tx` / `ledger2_op_log`。

```sql
CREATE TABLE IF NOT EXISTS ledger2_meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

-- M 节点。没有 op 列：M 恒 +1。parent_id IS NULL 就是根。
-- id 形如 'cat:<分类名>' 只是「平台分类预设」建出来的节点的命名约定（读出时标 kind=category）；
-- 它和普通 M 一样是一行真实记录，可以改名、移动、解散。
CREATE TABLE IF NOT EXISTS ledger2_node (
    id        TEXT PRIMARY KEY,
    parent_id TEXT REFERENCES ledger2_node(id) ON DELETE RESTRICT,
    name      TEXT NOT NULL,
    note      TEXT NOT NULL DEFAULT ''      -- 节点自己的备注，不参与金额
);
CREATE INDEX        IF NOT EXISTS idx_ledger2_node_parent ON ledger2_node(parent_id);
CREATE UNIQUE INDEX IF NOT EXISTS idx_ledger2_node_one_root
    ON ledger2_node((1)) WHERE parent_id IS NULL;   -- 有且只有一个根

-- +2 净额组。node_id 显式存组的位置。note = 人工备注（不参与金额）。
CREATE TABLE IF NOT EXISTS ledger2_net_group (
    id      TEXT PRIMARY KEY,
    name    TEXT,
    node_id TEXT NOT NULL REFERENCES ledger2_node(id) ON DELETE RESTRICT,
    note    TEXT NOT NULL DEFAULT ''
);

-- 归属 + 人工字段（同一行）。已初始化的交易**必有**一行 role='primary'
-- （没有「默认父节点」这回事）；分裂副本 t′ 同样必有一行 role='mirror'。
-- 没有行 = 没初始化 = 所有读出里都不存在。net_group_id 非空 = 属于某个 +2 组。
--   initialized   ：主行恒为 1（行存在即已初始化；0 只可能是坏数据，自检会报）
--   title / note  ：初始化前为空；初始化时可指定，之后可改（update_manual）
--   category_path ：初始化时写入的完整路径（JSON 数组，根以下各级节点名），之后不静默刷新
-- 镜像行不带人工字段（title/note/category_path 恒为空），也不允许写。
CREATE TABLE IF NOT EXISTS ledger2_tx (
    tx_id         INTEGER NOT NULL REFERENCES transactions_raw(id) ON DELETE CASCADE,
    role          TEXT    NOT NULL CHECK (role IN ('primary', 'mirror')),
    node_id       TEXT    NOT NULL REFERENCES ledger2_node(id) ON DELETE RESTRICT,
    net_group_id  TEXT    REFERENCES ledger2_net_group(id) ON DELETE RESTRICT,
    initialized   INTEGER NOT NULL DEFAULT 1 CHECK (initialized IN (0, 1)),
    title         TEXT    NOT NULL DEFAULT '',
    note          TEXT    NOT NULL DEFAULT '',
    category_path TEXT    NOT NULL DEFAULT '[]',
    PRIMARY KEY (tx_id, role)
);
CREATE INDEX IF NOT EXISTS idx_ledger2_tx_node  ON ledger2_tx(node_id);
CREATE INDEX IF NOT EXISTS idx_ledger2_tx_group ON ledger2_tx(net_group_id);

-- 分裂事实：一行 = 这笔交易有一个镜像副本 t′。
CREATE TABLE IF NOT EXISTS ledger2_split_tx (
    src_tx_id INTEGER PRIMARY KEY REFERENCES transactions_raw(id) ON DELETE CASCADE
);

-- 操作日志：正向原语序列 + 逆序列。state: applied / undone / discarded
CREATE TABLE IF NOT EXISTS ledger2_op_log (
    seq        INTEGER PRIMARY KEY AUTOINCREMENT,
    op_json    TEXT NOT NULL,
    undo_json  TEXT NOT NULL,
    state      TEXT NOT NULL DEFAULT 'applied' CHECK (state IN ('applied', 'undone', 'discarded')),
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

```

### 10.1 初始化 / 卸载 / 人工字段

| 概念 | 落点 | 规则 |
|---|---|---|
| **初始化** | `ledger2_tx` 的 primary 行（`initialized = 1`） | `ops.init_txs(conn, tx_ids)`：把交易放进节点（已有节点或当场新建）；可选把其中若干笔收进一个 +2 组（建组后自然合并，R1 同父校验）；可选给某些交易分裂（t′ 默认与 t 同位置，也可显式指定）。**每笔已初始化的交易和 t′ 都有显式归属行**；标题 / 备注 / 分类路径在同一次事务里写入。新建节点可带 `note`。二次初始化同一笔 → `ALREADY_INITIALIZED`，整批原子回滚。 |
| **读出前提** | `facts.load_txs` / `facts.scope_by_date` | 只输出 `initialized=1` 的主行；未初始化的交易在任何读出（全量树 / 范围投影 / 逐笔列表）里都不存在，**也不影响任何别的交易**。事实层不做退款 / 搬运配对：每笔交易按自己的方向与金额成为原子；净额由 +2 组表达（ν = 成员 ∩ scope）。 |
| **平台分类预设** | `presets.init_by_platform_category(conn, tx_ids=None)` | `tx_ids` 缺省 = 所有未初始化交易。为每个平台分类建 `cat:<分类名>` 节点（已存在则复用，`kind='category'` 由 id 前缀派生，不是列），逐笔放置，并把交易的不可变字段抄进人工字段：**标题 = 收支项目**（空则用对方户名）、**备注 = 交易备注**、**分类路径 = 节点完整路径**（根以下各级名字）。没有交易可初始化 → `NO_EFFECT`。 |
| **卸载** | 删 `ledger2_tx` 的主行（连带 t′ 的镜像行） | `ops.uninst_txs(conn, tx_ids)`：整行注销（初始化标记 / 标题 / 备注 / 分类 / 归属），撤分裂，把因成员不足 2 人而自动解散的组（R3）一并处理。撤销时用 `tx_restore` 原语**整行恢复**（人工字段和归属一起回来）。**原始交易行一个字节不动**；卸载后可以再初始化，字段回到空。 |
| **改标题 / 备注** | `ops.update_manual(conn, tx_id, title=None, note=None)` | 标题 / 备注可反复改；值没变 → `NO_EFFECT`。`category_path` 只在初始化时写一次，之后**静默刷新暂未实现**（设想是「工具读时顺手刷新」，性能待评估）。 |
| **改节点名 / 备注** | `ops.update_node(conn, node_id, name=None, note=None)` | 不给的字段不动；都没有变化 → `NO_EFFECT`。根节点**可以改备注、不能改名**（`CANNOT_RENAME_ROOT`）；`rename_node` 保留为只改名的窄包装。 |

`init` / `uninst` / `update_manual` 都是**普通操作**：和建树、移动一样进 `ledger2_op_log`
（op 名即 `init` / `uninst` / `update_manual`），可 undo / redo，撤销靠原语逆序列。

### 10.3 引擎层的 op 表单（`service.apply`）

引擎层把「选择 × 动作」收成 9 个 op（设计见 `proj/draft/10_账本代数V2-引擎层设计.md`）：

| op | 选择解释 | 必填 | 说明 |
|---|---|---|---|
| `init` | —— | 三选一：`style:'platform'` / `plan` / 缺省（全部未初始化） | `style` 和 `plan` 不能同时给；预设只拼 op |
| `create_node` | 最简 | `name` + `items` | 父 = 选区 LCA；`note` 可选 |
| `move` | 最简 | `items` + `target` | 集合移动，保结构 |
| `join` | 最简 + 必须全交易 | `items` + `group_id` | M / +2 → `JOIN_REQUIRES_TX` |
| `create_group` | 最简 + 必须全交易 | `name` + `items` | 名字去空白后为空 → `EMPTY_NAME` |
| `dissolve` | 最繁 | `items` | 批量；根被静默忽略 |
| `split` | 最繁后筛出未分裂的 t | `items`（或 legacy `tx_id`） | M / +2 摊成交易；t′ 与已分裂的 t 跳过；没有可分裂的 → `NOTHING_TO_SPLIT` |
| `unsplit` | 最繁后筛出已分裂的 t | `items`（或 legacy `tx_id`） | 没有可取消的 → `NOTHING_TO_UNSPLIT` |
| `update` | 单选 | `item` + `name` / `note` | 按引用类型分发：M / +2 / t；t′ → `MIRROR_HAS_NO_MANUAL` |

### 10.4 已知取舍（这一轮不做）

- **`category_path` 的静默刷新未实现**：初始化后如果节点改名 / 交易被搬走，`ledger2_tx` 里的路径
  不会跟着变。设计上它只是「初始化那一刻的完整路径」，不是实时字段。
- **前端 `/v2` 页在预设跑之前是空树**：读要求 initialized=1，而真库副本里一笔都没初始化 ——
  这正是「初始化是账本的前置步骤」的体现，接回方案里要把预设挂在首次进入 `/v2` 或迁移脚本上。
- **分类节点搬空后仍留在全量树**（值 0.00）；范围投影里不出现（N11）。

一个数据库文件 = 一本账（**没有 `book_id`**）—— 与 V1 的多账本不同，这是接回时要拍板的点之一
（见 `06_接回方案.md` 的 D1）。
