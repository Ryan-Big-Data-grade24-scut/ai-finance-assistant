# 06 · V2 接回方案（终点：V2 接管 `/api/ledger` 与 MCP）

> 状态：V2 已独立跑通（`backend/ledger2/` + `/api/ledger2/*` + 前端 `/v2`），**尚未接回**。本文只回答「怎么接」，每一步都能在真库**副本**上演练、能回滚。
> 红线：真库 `db/bills.db` 不被任何接回步骤直接写；先在副本上跑两遍且幂等。

## 1. 结论

V2 是**账本语义层的替换件**。要换的只有三样：

1. **存储**：V1 的 state-blob + `ledger_legs` → V2 的关系表 + 原语日志（`ledger2_*`）；
2. **语义**：V1 的「节点级 NET 标志」→ V2 的「+2 净额组（ν）+ scope 最小覆盖投影」；
3. **撤销**：V1 的整树快照 → V2 的原语逆序（所有操作可逆，Q4）。

**不用换的**：HTTP 壳、MCP 工具名、前端星图。V2 的嵌套树可以在后端摊平成 V1 的 flat `LedgerTree`，前端一行不改（见 §4）。

## 2. 两套模型逐项对照

| 维度 | V1（在跑） | V2（已实现） |
|---|---|---|
| 存储 | `ledger_history.state_json` 整树快照 + `ledger_legs` | `ledger2_node` / `ledger2_placement` / `ledger2_net_group` / `ledger2_split_tx` / `ledger2_op_log` |
| 归属 | `placements: tx_id → node_id`，每本账一份 | 无行 = 在默认父节点（分类虚拟节点）；有行 ⇔ 父≠默认父 或 在组里 |
| 平台分类 | 叶子/父节点落库，`v_tx.category` 优先取 V1 树叶子名 | 读时虚拟节点 `cat:<名>`，不落库；被移动/当父时在同一可逆操作里惰性落一行 |
| +2 | **没有**；只有节点级 `ADD/NET` | 组成员同父（R1）、整组不可分割（R2）、不足 2 人自动解散（R3），净额 = 成员 ∩ 范围 |
| 读 | `_filter_live_state` 过滤扁平节点 | `read_scope` 最小覆盖投影（范围内无交易的节点不出现） |
| 撤销 | 快照 | 原语日志 + 逆序列，undo/redo 同样过自检 |
| 分裂 | 要求 `funding ∈ {亲情卡, 他人代付}`，镜像腿进专用「外部收入节点」 | 无条件；t′ 是普通叶子（`role='mirror'`），零额交易不可分裂 |
| 口径 | `atoms.py`（退款配对/搬运/中性默认支出） | **复用同一份** `atoms.py`（`facts.py` 适配，口径只留一份） |
| 多账本 | 多本（`ledger_books` + `book_id`） | 一个库一本账 |
| 金额单位 | 内部分，HTTP 出口转元 | 内部分，API 也是分（前端换算） |
| 对外形状 | flat：`{root_id,nodes[],transactions[],legs[],root_e,root_i,root_net,…}` | 嵌套：`{type:node\|group\|tx, children[]}` |

**一个必须知道的耦合**：`v_tx.category` 会优先取 V1 树的叶子名。V2 因此**不用** `v_tx.category`，分类只取 `tx_overrides.manual_category` → `transactions_raw.tx_type` → `其他`。V2 接管后，报表的分类口径来源会变，第一轮报表要单独对账（M3）。

## 3. op 映射

| V1 op | V2 引擎 op（`service.apply`） | 备注 |
|---|---|---|
| `create_node`（显式 `parent_id`、`tx_ids`） | `create_node`（`items`，父=选区 LCA，被覆盖项按最简折叠） | V2 的选区可混合 t / M / +2 |
| `reassign`（逐笔） | `move`（`items` + `target`，集合移动，保结构） | V1 逐笔 → V2 一次集合移动 |
| `dissolve_node` | `dissolve`（`items`，按最繁展开；批量、一次撤销） | V1 一次只能解散一个节点 |
| `attach_tx` / `detach_tx` | `move` 到目标节点 | 归属是显式行，没有「默认父节点」 |
| `split` / `unsplit` | `split` / `unsplit`（`items` 批量，或 legacy `tx_id`） | V2 去掉 funding 限制 |
| `set_op`（节点 NET） | **无对应物** → `create_group`（+2 组） | 见决策点 D2 |
| —— | `init`（`style` 预设 / `plan` 自定义 / 缺省全部未初始化） | 初始化在引擎层，预设只拼 op |
| —— | `join`（`items` 全部为交易 + `group_id`） | 加员；M / +2 不许进组 |
| —— | `create_group`（`name` 必填 + `note` 可选） | 建组 |
| —— | `update`（`item` + `name` / `note`，按引用类型分发到 M / +2 / t） | 改名、备注 |
| `undo` / `redo` / `reset` | `undo` / `redo` | `reset` 在 V2 = 反复 undo 或清日志，需另定 |

legacy 名字（`dissolve_node` / `rename_node` / `add_member` / `remove_member` / `rename_group` /
`dissolve_group` / `update_manual` / `update_node`）仍然可用，但前端只走上面这组引擎 op。

HTTP 现状：`/api/ledger2/tree`（GET）、`/op` `/undo` `/redo`（POST）；错误体 `{code,message,detail}`，状态码 404/409/400。

## 4. 响应形状：前端怎么不改

接管 `/api/ledger/*` 时，`service` 加一层 flat 投影（后端内部，不动前端）：

| V2 对象 | flat 里 |
|---|---|
| M 节点 / 分类节点 | `{id,parent_id,name,kind,op:'ADD',e,i,net,count}`（分类节点 `kind:'group'`） |
| +2 组 | 也作节点：`{id:group.id,parent_id:group.node_id,op:'NET',…,count:成员数}`，前端本来就给 `op==='NET'` 画 `≈` |
| 交易 | 进 `transactions[]`，`node_id`=归属节点（组内成员填 group.id） |

金额出口转元。唯一要前端处理的差异：V2 新增了「创建 +2 组 / 加入 / 移出」手势，星图要么沿用 NET 节点的呈现，要么加入口——这是产品决策，不是接回的阻塞项。

## 5. 迁移步骤 M0–M6

每步在**真库副本**上演练；回滚列出该步的退路。

| 步 | 做什么 | 验证 | 回滚 |
|---|---|---|---|
| M0 影子读 | V2 只读副本，和 V1 树并排输出；根 e/i、每分类聚合逐分对账 | 差额必须 0；不为 0 先查口径，不许「差不多」 | 只读，无需回滚 |
| M1 建表 | 副本上跑 `python -m backend.ledger2.migrate --db <副本>`（需显式路径） | 表齐全、幂等重跑不报错 | drop `ledger2_*` |
| M2 搬数据 | V1 live book 的 `ledger_nodes`/`ledger_placements`/`ledger_legs` → `ledger2_node`/`ledger2_placement`（+ 分裂 → `ledger2_split_tx`） | 搬完 V2 全量读的根值 = V1；跑两遍幂等 | 清 `ledger2_*` 重搬 |
| M3 读切 V2 | `/api/ledger/tree` 的实现换成 V2 + flat 投影；报表分类口径同步复核 | 前端星图截图对比；`pytest` 全绿 | 路由改回 V1 实现 |

| M5 撤销机制切换 | 快照 → 原语日志 | **不可逆**：旧历史语义改变，必须先在副本演练 | 保留 `ledger_history` 不删，只停写 |
| M6 V1 下线 | 归档 `ledger_books/nodes/placements/legs/history`（参照 `db._archive_legacy_ledger`） | 归档后全套测试仍绿 | 归档表可原样还原 |

## 6. 需要你拍板的决策点

- **D1 多账本还留不留**：V2 是一库一账。前端有 `book_id`；留的话 V2 的 `ledger2_*` 全要加 `book_id`，护栏与 invariants 都要改。
- **D2 V1 的节点级 NET 往哪迁**：已有的 NET 节点要变成「该节点下的一个 +2 组」还是保留为节点标志？前者语义干净，后者不丢 V1 用户的既有结构。
- **D3 「外部收入节点」下架**：V1 的镜像腿在专用节点，V2 的 t′ 是普通叶子，位置由用户定。迁移时 t′ 默认落在源交易的分类节点（`ledger2` 默认规则），是否接受。
- **D4 `收益发放` 例外**：中性交易默认记支出、`收益发放` 例外这条在 V1 `atoms.py`；V2 复用它，所以接回时不用重写——但接管后 `atoms.py` 是否整体搬进 `backend/ledger2/`。
- **D5 审计链**：V1 的 invariants I1–I6 + 审计元数据，V2 保留哪些。V2 现有自检：唯一根、每笔恰一个父、组成员 ≥2 且同父（R1）、树无环。

## 7. 风险与不可逆点

| 风险 | 应对 |
|---|---|
| 报表分类口径在 M3 后变化（不再受 V1 树叶子名影响） | M3 单独对账一轮 |
| M5 撤销机制切换改变既有历史语义 | 副本演练；`ledger_history` 保留不删 |
| 真库误写 | 所有 M0–M5 只在副本；真库写入只发生在用户确认后的正式切换 |
| V2 表名与 V1 近似看错表 | `ledger2_` 前缀；护栏禁止 `backend/ledger2` 写 `ledger_*` |
