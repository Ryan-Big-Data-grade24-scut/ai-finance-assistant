# 06 · V2 成品化蓝图与进度

位置：`proj/ai-finance-assistant-v2`（兄弟目录 + git 分支 `v2`，由正式仓库 `e1d7e91` 克隆，无真实数据，未提交）。

## 一、蓝图

| 层 | 内容 |
|---|---|
| `backend/ledger2/` | `algebra` `model` `errors`（纯）；`schema.sql` `store`（`ledger2_*` 表，不进 `db/schema.sql`）；`facts`（唯一读业务表，只复用 V1 `atoms` 的方向/中性规则，**不做退款配对**；分类=手工覆盖→`tx_type`→其他）；`ops`（原语+用户操作+初始化/卸载/人工字段+撤销重做）；`presets`（平台分类初始化预设）；`reader`（全量/scope 投影/JSON）；`invariants`（写后自检）；`service` `api`（`/api/ledger2/*`，金额用分）；`migrate`（建表 CLI） |
| 关键设计 | 交易必须先初始化才读得出来（`ledger2_tx` 的 primary 行 = 归属 + 人工字段同一行）；已初始化交易和分裂副本 t′ **必有一行显式归属**；节点有 `note`，可随初始化写入、用 `update_node` 改；平台分类预设建出 `cat:<名>` 真节点（可改名 / 移动 / 解散）；退款净额一律由 +2 组表达（事实层不配对）；+2 组同父不放宽、整组不可分、不足 2 人自动解散、净额=成员∩范围 |
| 前端 | `/v2` 页：树、日期范围投影、建 M / 建 +2 组 / 移动 / 解散 / 分裂、撤销重做、历史 |

## 三、已知小毛病

- `category_path` 只在初始化时写一次，节点改名 / 交易搬走后不会跟着刷新（静默刷新暂未实现）。
- 真库副本跑平台预设之前，`/v2` 页是空树（读要求 initialized=1）——接回时要把预设接到迁移脚本或首次进入。
- `NODE_NOT_FOUND` 的提示文字对节点 id 也写成「分组 … 不存在」。
- 历史面板里个别操作名没有中文标签时回退显示原名。
- 前端只做了 `/v2` 页，星图（`/star`）仍是 V1。
