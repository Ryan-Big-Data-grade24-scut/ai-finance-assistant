# 记账代数

> 定义「怎么把一堆交易算成一个账」。本文只有数学，不含任何具体账本的数据。

---

## 1. 四种基本类型

### 1.1 原子交易 τ

账本里不可再分的一行，由平台导出，**任何人、任何脚本都不能修改**。

```
τ := ( id,  s,  a,  d )
      id  唯一标识
      s   平台给出的方向 ∈ { +1, 0, −1 }
      a   金额 ∈ ℝ₊
      d   平台给出的描述（商户、分类、时间、支付方式…）
```

* `s` 是**平台的事实**，不是判断
* 平台把方向记错、把支出记成「中性」是常见情形，`s = 0` 必须能被后续处理

### 1.2 交易集 X

```
X := { τ₁, τ₂, …, τₙ }        一个待计算的账期内的全部原子
X ∩ X′ = ∅                    不同账期不相交
```

`X` 是**给定的**。所有记账工作的输入只有它。

### 1.3 结果 Y

```
Y := ( e,  i )        e, i ∈ ℝ₊
```

选有序对而非带符号标量，是因为报表要分开展示「花了多少」与「进了多少」，
净差 `i − e` 是派生量，随时可算，不单独存储。

### 1.4 记账方式 M

```
M :  X  →  Y
```

**M 是一个函数，不是一套规则。** 同样的 X 换 M 就换 Y —— 这是本代数的出发点：

```
X = { 收入 100, 支出 100 }                 同一批交易

M_A(X) = (100, 100)        收入 100，支出 100
M_B(X) = (0, 0)            净额化：两两抵消
M_C(X) = (0, 200)          只认支出、忽略收入（口径错误，仅作反例）
```

> **推论 1：记账不是「事实」，是 X 在某个 M 下的像。**
> 讨论「这个月花了多少」时，隐含地已经选定了 M。
> 所以所有口径分歧都不是事实分歧，而是**选 M 的分歧**。

## 2. 原子算子

**本部分只处理一件事：把一个原子 τ 变成它的腿。**
层级相关的规则在第 3 部分。

### 2.1 `atom(τ)` —— 原子 → 单腿

```
atom(τ) = ( a, 0 )    若 s = −1        支出
atom(τ) = ( 0, a )    若 s = +1        收入
atom(τ) = ( 0, 0 )    若 s =  0        中性：平台没给出方向
```

`s = 0` 默认产出零，但这只是**默认值，不是判决**。
`atom` 是 M 的一部分，换 M 就换这个默认值。

### 2.2 `+_1` 叠加

```
( a₁, i₁ ) +_1 ( a₂, i₂ ) = ( a₁ + a₂ ,  i₁ + i₂ )
```

交换、结合，单位元 `(0,0)`。**纯双边累加，不做任何判断。**

### 2.3 `+_2` 净额

先 `+_1`，再取净额。**净额恒为正，归哪边由符号定**：

```
x +_2 y = net( x +_1 y )

        ⎧ ( 0 ,  I − E )      若 I ≥ E        净流入 → 记收入
net(E,I)=⎨
        ⎩ ( E − I , 0 )      若 E > I        净流出 → 记支出
```

**幂等嵌套**（第 3 部分会用到）：

```
net( net(X₁) +_1 net(X₂) ) = net( X₁ +_1 X₂ )        ∀ 有限正负组合
```

> **约束**：`+_2` 只能作用在**已完成 `+_1` 聚合**的集合上。
> 不能边聚合边净额化 —— 那会让先净额化的部分吞掉后净额化的正负。

### 2.4 `split(τ)` 分裂 —— **仅对涉及外部额度的 τ 生效**

有些 τ 需要变成两条腿才说得清。但这条规则**有严格适用域**：

```
可分裂  ⟺  τ 涉及「自己名下之外的账户」所授予的资源额度
```

| τ 的性质 | 可分裂 |
|---|---|
| 消费、收入、普通转账 | ❌ 不分裂 |
| 账户之间的划转（自己的账户互转） | ❌ 不分裂 |
| 池子之间的搬进搬出（自己的池子） | ❌ 不分裂 |
| 涉及**外部额度**（额度归属方在自己名下之外） | ✅ 分裂 |

**为什么范围必须限定**：分裂会凭空增加一笔镜像流入。
对普通交易这么做毫无依据，只是把一条腿平白变成收入。
只有当 τ 真的消耗了**外部资源**时，「一去一来」才是事实。

在此范围内，分裂规则为：

```
split(τ) :  τ ⟶ ℓ₁ +_1 ℓ₂ ,   其中 ℓ₂ = mirror(ℓ₁)

支出 τ:   ℓ₁ = ( a, 0 )      ℓ₂ = ( 0, a )
收入 τ:   ℓ₁ = ( 0, a )      ℓ₂ = ( a, 0 )
```

分裂把「一笔消耗外部额度的流动」拆成「**一条去路** + **一条来源**」。

两条腿的**金额恒相等、方向恒相反**，这是分裂的不变式：

```
ℓ₁ +_1 ℓ₂ = ( a, a )        对任意可分裂的 τ 成立
```

> **分裂不守恒。** 它把 `(a,0)` 变成 `(a,a)`，总账**增加了一笔镜像**。
> 对涉及额度的 τ，这笔镜像**必然是真实的外部流入** ——
> 因为额度本身就不在你名下，它是外部资源，消耗它就是外部资源的流入。
>
> 所以这里没有「内部/外部」的分岔：**能分裂，就一定是外部的。**
> 不能分裂的，一律走单腿。

### 2.5 `refund(τ)` 退款合并 —— 优先级最高，先于分裂

```
IF ∃ 配对退款腿 τ_ref （金额相等、方向相反、指回同一来源） THEN
    atom(τ) +_2 atom(τ_ref) = ( 0, 0 )
    τ_refunded = True
ELSE
    τ_refunded = False
```

**顺序铁律：先合并退款，再决定是否分裂。**

理由：退款意味着资源回到了原处，**既没消费、也没获得**。
若先分裂再去合并，退款腿会分裂出第三条腿，抵消关系被破坏，
容易凭空多出一笔外部流入。

先归零再分裂：`(0,0)` 分裂仍是 `(0,0)`，**不会漏**。

### 2.6 腿的生成（原子算子的最终产物）

对每个 τ，按下表产出腿集合 `legs(τ)`：

```
IF τ 有配对退款腿              →  legs(τ) = { ℓ = ( 0, 0 ) }                  1 条，值为零
ELIF τ 涉及外部额度（§2.4）   →  legs(τ) = { ℓ₁, ℓ₂ = mirror(ℓ₁) }        2 条，一去一来源
ELSE                          →  legs(τ) = { ℓ₁ = atom(τ) }                 1 条
```

**三种情形互斥且穷尽。** 分支顺序不可交换 —— 退款检查必须在分裂之前。

> **推论 2：所有记账判断都在原子层完成。**
> 节点层不重新解释任何一笔交易，它只做聚合。
> 好处：判断集中可审计，聚合逻辑简单到不可能出错。

## 3. 从原子到层级

腿已经生成完毕。本部分回答：**腿怎么组成一张分层的账。**

### 3.1 腿是层级的最小单位

原子层结束后，全账只剩两种东西：

```
腿 ℓ     每条腿是一个 (e, i)，且 ℓ 恰好属于一笔原子 τ
节点 n   每个节点是一组腿，或一组子节点
```

**层级不再改变任何一条腿的值。** 它只决定腿被谁聚合。

### 3.2 层级树的定义

记账账本是一棵**有根树**（或森林 + 虚拟根）：

```
节点 n := ( id,  name,  op,  legs(n),  children(n) )
                 op ∈ { ADD, NET }
```

* **叶子节点**：`children(n) = ∅`，`legs(n) ≠ ∅`
* **内部节点**：`children(n) ≠ ∅`，`legs(n) = ∅`
* **根**：整棵树（可设虚拟根把森林连起来）

两条硬约束：

```
(C1) 腿的唯一归属      ∀ ℓ ∈ ⋃ legs(τ): 恰好存在一个节点 n 使 ℓ ∈ legs(n)
(C2) 腿的完备性        ⋃ legs(τ) = 所有 τ 的全部腿
```

### 3.3 节点的聚合规则

节点 `n` 的值**只由直接子节点（或直接腿）的值决定**，与它的 `op` 一起：

```
Y_n = op_n ( ⨆_{x ∈ children(n) ∪ legs(n)} Y_x )
Y_ℓ = ℓ                                   对腿 ℓ
```

其中 `⨆` 是 `+_1`。

| `op_n` | 定义 | 用途 |
|---|---|---|
| `ADD` | `Y_n = ⨆ Y_x` | 普通分类：各子项直接相加 |
| `NET` | `Y_n = net( ⨆ Y_x )` | 净额组：组内正负相抵后取净额 |

`op_n` 只有这两种。**不需要第三个算子** ——
凡是「不该进报表」的东西，都在第 2 部分的腿生成阶段就处理掉了。

### 3.4 层级的递归定义

对任意节点 `n`，记其子节点为 `n₁, …, n_k`：

```
X_n = ⨆_{j=1}^{k}  X_{n_j}                  子节点的交易集互不相交，且并集为父集合
Y_n = op_n ( ⨆_{j=1}^{k} Y_{n_j} )
```

于是沿根到叶的任意路径都可反复展开：

```
Y_n = op_n ( ⨆ op_{n_j} ( ⨆ ... op_{leaf} ( ⨆ ℓ ) ) )
```

> **推论 3：层级只是 `+_2` 与 `ADD` 的嵌套顺序不同。**
> 「按什么顺序聚合」是账本结构；「聚合成什么」是算子行为。二者正交。

### 3.5 退化情形 = 平台预设账本

若整棵树只有一层（根 + 全部腿），且 `op = ADD`：

```
Y = M₀(X) = +_1 ⨆_{i=1}^{n} atom(τᵢ)
```

**这就是平台账单默认做的事** —— 把每一笔原样加进去，不做任何判断。
它不是「没有结构」，是**深度为 1 的退化树**。

> 所有更复杂的账本都是它的推广：
> * 加深度 = 分组
> * 换 `op` = 净额化
> * 换腿生成 = 分裂与退款处理（第 2 部分）

## 4. 三个例子

### 例一 · 叠加

```
τ₁ : 收入 1000
τ₂ : 支出 100
τ₃ : 支出 105

都不涉及外部额度 ⇒ 不分裂
Y = atom(τ₁) +_1 atom(τ₂) +_1 atom(τ₃)
  = (0,1000) +_1 (100,0) +_1 (105,0)
  = (205, 1000)
```

### 例二 · 净额（`NET` 节点）

```
τ₁ : 支出 100        替长辈垫付的采购
τ₂ : 支出 23         另一笔采购
τ₃ : 收入 500        长辈后来转回

都不涉及外部额度 ⇒ 不分裂
三个 τ 同组，op = NET：

Y = net( atom(τ₁) +_1 atom(τ₂) +_1 atom(τ₃) )
  = net( (123,0) +_1 (0,500) )
  = net( (123, 500) )
  = ( 0, 377 )
```

**语义**：这三笔合成「一件事」。
不想让它显示成 123 的支出（那只是中间态），但账上确实多了 377。
净额化后只记收入 377。

> 换成 `ADD` 就得到 `(123, 500)` —— **同一个 X，不同的树结构**。
> 这正是 §1.4 的「换 M 换 Y」在层级上的体现。

### 例三 · 额度（分裂，适用域内）

**前置说明**：本例的 τ₁ τ₂ τ₃ 全部**涉及外部额度**，因此适用 §2.4 的分裂规则。
若换成自己账户之间的转账，则**不分裂**，直接按单腿 `atom(τ)` 处理。

```
τ₁ : 支出 9.5        消耗外部额度，无配对腿
τ₂ : 支出 50         用外部额度转出
τ₃ : 收入 50         转出去处收到（τ₂ 的配对腿）
```

**分支 A · 真消费（`τ₁`）**

```
legs(τ₁) = { ℓ₁ = (9.5, 0),  ℓ₂ = (0, 9.5) }

ℓ₁ → 消费节点        （钱花掉了）
ℓ₂ → 外部收入节点    （额度替你买单）
```

**分支 B · 转出（`τ₂`，有配对腿 `τ₃`）**

```
legs(τ₂) = { ℓ₁ = (50, 0),  ℓ₂ = (0, 50) }
legs(τ₃) = { ℓ₃ = (0, 50) }

ℓ₁ 与 ℓ₃ 同组 NET：  net( (50,0) +_1 (0,50) ) = ( 0, 0 )
ℓ₂ 单独进外部收入节点   ← 额度转出后新出现的资源
```

**顺序不能乱**：

| 做法 | 结果 | 判断 |
|---|---|---|
| 只 `NET` 不分裂 | `(0, 0)` | ❌ 额度转出确实产生了新资源，账面凭空蒸发 |
| 只分裂不合并 | 流入算两次 | ❌ 虚增收入 |
| **先分裂再 `NET`** | `ℓ₂` 留一笔外部收入 | ✅ |

**分支 C · 退款（优先级最高，先于以上所有）**

```
τ₄ : 支出 9.5        原本的扣款
τ₅ : 收入 9.5        退款（τ₄ 的配对腿）

先合并：  atom(τ₄) +_2 atom(τ₅) = net( (9.5,0)+_1(0,9.5) ) = ( 0, 0 )
再分裂：  (0,0) ⟶ (0,0) +_1 (0,0) = ( 0, 0 )

既不计消费，也不计收入，但痕迹仍留在账上。
```

**分支 D · 对照：不涉及额度的普通转账（禁止分裂）**

```
τ₆ : 支出 50         自己账户 A → 账户 B
τ₇ : 收入 50         账户 B 的对侧记录

不满足 §2.4 的适用条件 ⇒ 禁止分裂 ⇒ 各一条单腿：
legs(τ₆) = { ℓ = atom(τ₆) = (50, 0) }
legs(τ₇) = { ℓ = atom(τ₇) = ( 0, 50) }

若归入同一 NET 节点，得 (0,0)；
若分开进不同节点，一支是消费一支是收入 —— 那就说明它们不是同一件事，
应当先问清楚，而不是靠分裂掩盖。
```

## 5. 不变量与恒等式

下列性质对**任意**合法账本成立，且应当被机器检查：

```
(I1) 腿的唯一归属      ∀ ℓ ∈ 所有腿:  |{ n : ℓ ∈ legs(n) }| = 1

(I2) 腿的完备性        ⋃_n legs(n) = ⋃_τ legs(τ)

(I3) 分裂对称          ∀ τ 涉及外部额度: ℓ₁ +_1 ℓ₂ = ( a, a )

(I4) 分裂去向唯一      ∀ τ 涉及外部额度: ℓ₂ 计入外部收入节点（无其他可能）

(I5) 节点可加性        ∀ n:  Y_n = op_n( ⨆_{c} Y_c )     （定义即恒等）

(I6) NET 幂等          net( net(X₁) +_1 net(X₂) ) = net( X₁ +_1 X₂ )
```

**审计链**（从原始原子走到根）：

```
①  Σ τ 的原始有符号和   Σ s(τ)·a(τ)
②  + 中性定向产生的变化   （把 s=0 的 τ 按归属赋方向）
③  + 分裂新增的镜像和     Σ_{ℓ₂} (i − e)
④  + NET 重排的影响       ≡ 0                （I6）
⑤  = 根的净值            i(root) − e(root)
```

**恒等式必须闭合。** 不闭合意味着有交易在变换中凭空出现或消失 ——
那是实现缺陷，不是口径分歧。**口径分歧永远是链路上的一行；缺陷是不在链路上的东西。**

## 6. 完备性与终止

一轮记账何时算完？三个条件**并列**：

```
(T1) 完备        legs 归属覆盖所有 τ，无孤儿
(T2) 一致        六条不变量全部成立
(T3) 目的达成    用户认为够细了          ← 唯一无法机器判定的条件
```

### 6.1 推进的不变式

每推进一轮，维护：

```
X     = 全部原子（固定，永不改变）
X_rest = 尚未产生腿的原子
M_before = 已完成节点的净值

X = X_done ⊎ X_rest ,      X_done ⊎ X_rest = X
M_before = ⨆_{n ∈ 已完成节点} Y_n
```

每轮结束时必须成立：

```
M_before′ = M_before +_1 M_current
X_rest′   = X_rest \ X_current
| M_before′ +_1 X_rest′  −  M(X)  | = 0
```

最后一条就是 **I5 沿根展开**，是每轮都必须过的检查。

### 6.2 收敛

```
X_rest 严格递减，每轮至少减少 1 个原子
⇒ 有限轮后 X_rest = ∅
```

但 `(T1) ∧ (T2) ∧ (T3)` 中，只有前两条能自动判定。
**`(T3)` 必须由人回答** —— 所以流程的正确形态是：

```
机器负责：报告客观状态（X_rest 还剩多少、断言是否通过）
人负责  ：判断够不够细
```

把这两件事混在一起，要么机器替人做决定（危险），
要么人重复机器能算的东西（低效）。

## 7. 记号表

| 记号 | 含义 |
|---|---|
| `τ` | 原子交易，平台导出，不可变 |
| `s(τ), a(τ)` | 原子的方向与金额 |
| `X` | 交易集，记账的输入 |
| `M` | 记账方式，`M : X → Y` |
| `Y = (e, i)` | 结果，支出分量与收入分量 |
| `atom(τ)` | 原子 → 单腿 |
| `split(τ)` | 分裂成两条腿，**仅对涉及外部额度的 τ** |
| `refund(τ)` | 退款合并，优先级最高 |
| `+_1` | 叠加，双边累加 |
| `+_2` | 净额，先累加再取净额 |
| `ℓ₁, ℓ₂` | 腿 |
| `legs(τ)` | 原子 τ 产出的全部腿 |
| `ADD` / `NET` | 节点算子 |
| `⨆` | 子节点值的 `+_1` 聚合 |
| `⊎` | 集合的不相交并 |
| `X_rest` | 未产生腿的原子 |
| `M_before` | 已完成节点的净值 |

## 8. 三句话总结

1. **交易是事实，记账是函数。** 同一个 `X` 在不同 `M` 下得到不同 `Y`，
   所以口径分歧永远是「选哪个 M」，不是「事实是什么」。

2. **所有判断在原子层，所有聚合在节点层。**
   第 2 部分只干一件事：把 τ 变成腿（`atom` / `split` / `refund`）。
   第 3 部分只干一件事：把腿聚成树（`ADD` / `NET`）。
   **分裂有严格适用域**：只对涉及外部额度的 τ 生效，其余一律单腿。

3. **完备性是可验证的，目的性不是。** 不变量能证明「没有交易被漏掉或重复」，
   但证明不了「够细了」—— 那是人要回答的。
   系统的职责是把前者每次都算清楚，让后者只需要回答一次。
