## 一、原文（逐字）

> 我觉得这个2.1的核心函数层很不能承载真正的账本
>
> 我们先从数学层面出发去思考一下怎么样把账本给"存"下来？
>
> 原本的 `docs/设计/第二轮/记账代数.md` 是有问题的 并且探讨的是局限于纯数学层面的
>
> 现在我们需要结合数据库、数据结构这些来思考
>
> 直观来说 账本可以由每一笔交易 及这些交易的关系构成
>
> 所谓关系分为两类：
>
> 一种是交易与交易之间的关系 分为 +_1 和 +2
>
> 另一种是 树状关系 举个例子 一开始是根节点 M_R 直接连接着所有的交易 随着我们进行进一步分类 会出现 M_1 、M_2 。。。这样
>
> 同一个 M 下的所有交易 t 它们一开始是 `[t1, t2, ...., tn]+1`
>
> 但也会存在 `[t1, [t2, t3, t4]+2, t5, ..., [..]+2, ..., tn]+1`
>
> 我觉得可以让数据库里面这么做
>
> 我们一步一步来：
>
> **首先 我们如果不考虑 +_2 和树状结构那么这个东西要怎么样存储、写入、读出呢？**
>
> 我们只需要原始的表 存着每一笔交易；然后需要的是有点像类 但我其实不是很理解这个数据库里面是怎么样跟类的实现结合 我的意思是 你需要让每一笔交易 都自动计算出它的 IE 向量 收入和支出 通常 它要么是收入 要么是支出；但我又觉得不太需要 比如说我定义这个 `[]` 操作 让它 `[t1] = （100，0）` 举个例子这样
>
> 就这样吧 我们用一个 `[]` 代表 atom 吧
>
> 然后我们的读出很简单 就是 `[[t1], [t2], ..., [tn]]+1`
>
> 然后也不存在什么写入操作
>
> **接着 如果考虑 +_2 呢（在一个可以任意选择的时间范围内）？**
>
> 这个时候就需要有数据表 存储着每一个 +_2 关系集合
>
> 比如我一条的栏目 那么它有一个独立的 id 然后后面就是一个数组 不定长度 包含每一个被纳入里面的
>
> 比如我原本是 `[t1, t2, t3, t4, t5, ..., tn]+1`（默认 `[t1]` 我直接写作 t1）
>
> 然后我现在是建立一个 +2 的关系：里面包含 t2 t3 t4
>
> 那么我们要在表里面新建一个 t2、t3、t4 的条目 并且给 t2 t3 t4 进行标记
>
> 最后我们在读出的时候需要：
>
> `[t1, [t2, t3, t4]+2, t5, ..., ..., tn]+1`
>
> 我们要做的就是一开始我们丢进去的是 f_+1(t1, t2, t3, t4, t5, ...., tn) 然后检查里面是否由东西被标记了
>
> 如果有 那么在表里找到那个 +2 条目 把在 t1, t2, t3, t4, t5, ...., tn 里面的 用 +2 的方法读出 比如 如果我有一个 +2 条目是 t2 t3 t4 t114514 我们就只 +2 这个 t2-t4
>
> 那么有两种操作 就是需要给新建 +_2 条目 和 从 +_2 条目中增删东西
>
> **再进一步 我们如何考虑有 +2 且需要树状结构的账单呢？**
>
> 首先 我们先思考 如果没有 +2 那么如何做这个树状结构（需要考虑时间）
>
> 比如 有一个分类 在去年是生效的 但今年的所有交易都不属于这个分类 那么这个分类就不要出现在我最后的计算中
>
> 我们最后需要返回的是 一棵树 这棵树是我当前时间范围内的所有 M 和 t 节点 并且我要给每一个 M 节点计算出它的 IE 向量
>
> 很显然 我觉得可以这样 比如我一开始 就有一个默认根节点 M_r 所有 t 的祖先都必须是它 这样 无论我们选择的时间范围是什么时候 它都能够成为那个根
>
> 也就是不会出现分散的树
>
> 我们计算的时候 首先 我们会输入这段时间的所有 t：t1， t2， t3， t4， t5, ..., tn
>
> 然后我们可以找到一棵最小的树 能够把 t1->tn 给涵盖在内：`M_r --> M_1, M_2 --> M_11, M_12, M21, M22 --> t1, .....`
>
> 最后 再对每个里面的 M_* 进行 `[]+1` 计算
>
> 其实如果有 +2 关系也很好算 就参考上面的计算方式即可
>
> 所以这里的操作在于：
>
> 1. 创建新的 M_** 默认至少需要选择一个 t，M_** 自动成为它的父亲节点；如果有多个节点被拖进来创建 则它们必须是同一个根节点下的（或者说 比如我 t1，t2，t3， M_12 都被拖进来 其中 t2 t3 的父节点是 M_12；M_12 和 t1 的父节点是 M_1 那么 我自动排除掉 t2 t3）
> 2. 要将某个交易 t 移动到某个 M 下 或者某个 M 进行同样的操作 分类讨论一下：一个 t 多个 t 一个 M 多个 M M-t 组合 当然 不管怎么样 数学上 都可以计算出一个唯一的移动集合 并且这个集合里面还是保留了结构的 `[M_1, t1, t2]` 就是它们几个是不可合并的 然后要做的就是把它们放到我们指定的 M 下
> 3. 如果要在某几个 t 里面创建 +2 关系 必须确保从根节点到它们的路径一致（不能跨 M 创建 +2 关系 M 与 M 之间 必须是纯粹的 +1 关系）
>
> 上面的基本上完备了 但还是缺少了分裂
>
> 不过分裂实现起来很简单 就是选择某个 t 分裂之后 它相当于多出来一个独立的 t' 并且 IE 向量是刚好反过来的；t' 自动继承 t 的路径 但不继承其 +2 关系；同一个 t 只能分裂一次 分裂出来的 t' 不能继续分裂 对 t 或者 t' 都可以进行取消分裂操作；取消分裂操作 只会把 t' 砍掉
>
> t' 需要存在一张表里面
>
> 我们先把这个代数在新的地方实现出来吧 我们先把它构建成一套完备的数学理论 然后再把它做成一整套完整的实现

## 二、拆成可判定的条目（供反复对照）

| 编号 | 条目 | 出处 |
|---|---|---|
| N1 | 账本 = 每笔交易 + 交易之间的关系；关系分两类：交易之间（+1 / +2）、树状关系 | 「账本可以由每一笔交易 及这些交易的关系构成」 |
| N2 | 不考虑 +2 和树时：只需原始表存每一笔交易；**无写入操作** | 「首先…要怎么样存储、写入、读出呢？」 |
| N3 | 每笔交易要**自动计算出它的 IE 向量** | 「你需要让每一笔交易 都自动计算出它的 IE 向量」 |
| N4 | `[]` 就是 atom：`[t1] = (100, 0)` | 「我们用一个 `[]` 代表 atom 吧」 |
| N5 | 读出 = `[[t1], [t2], ..., [tn]]+1` | 「然后我们的读出很简单」 |
| N6 | +2 需要一张表：每个 +2 关系集合一行，有独立 id，成员是**不定长数组** | 「它有一个独立的 id 然后后面就是一个数组 不定长度」 |
| N7 | 建 +2 时要**给成员做标记** | 「要新建一个 t2、t3、t4 的条目 并且给 t2 t3 t4 进行标记」 |
| N8 | 读出时：先按 +1 铺开，再检查哪些被标记，成组地用 +2 读出 | 「检查里面是否由东西被标记了…用 +2 的方法读出」 |
| N9 | +2 条目里的成员**可以不在当前范围内**，只对范围内的那部分做 +2 | 「一个 +2 条目是 t2 t3 t4 t114514 我们就只 +2 这个 t2-t4」 |
| N10 | +2 条目只有两种操作：新建、增删成员 | 「需要给新建 +_2 条目 和 从 +_2 条目中增删东西」 |
| N11 | 分类若在当前时间范围内没有交易，**不出现**在最终计算中 | 「去年是生效的 但今年的所有交易都不属于这个分类 那么这个分类就不要出现在我最后的计算中」 |
| N12 | 最终返回一棵**树**：当前时间范围内的所有 M 和 t 节点，每个 M 算出 IE 向量 | 「我最后需要返回的是 一棵树」 |
| N13 | 有默认根节点 M_r，所有 t 的祖先必须是它；不会出现分散的树 | 「所有 t 的祖先都必须是它」 |
| N14 | 计算流程：输入这段时间的所有 t → 找到能涵盖它们的**最小树** → 对每个 M 做 `[]+1` | 「我们可以找到一棵最小的树…最后 再对每个里面的 M_* 进行 []+1 计算」 |
| N15 | 有 +2 时，计算方式同上 | 「其实如果有 +2 关系也很好算」 |
| N16 | 操作 1：建新 M，至少选一个 t；新 M 成为被选项的父亲；被拖进来的节点若是同一父节点下的其它节点的子节点，**自动排除** | 「创建新的 M_**…我自动排除掉 t2 t3」 |
| N17 | 操作 2：移动。**分类讨论**（一个 t / 多个 t / 一个 M / 多个 M / M-t 组合），但最终能算出**唯一的移动集合**；集合内保持结构 `[M_1, t1, t2]`，彼此不可合并 | 「都可以计算出一个唯一的移动集合…它们几个是不可合并的」 |
| N18 | 操作 3：建 +2 关系必须**路径一致**，不能跨 M；M 与 M 之间只能是纯 +1 | 「不能跨 M 创建 +2 关系 M 与 M 之间 必须是纯粹的 +1 关系」 |
| N19 | 分裂：产生独立 t'，IE 向量**刚好反过来**；t' 继承 t 的路径，**不继承其 +2 关系**；一个 t 只能分裂一次；t' 不能再分裂；对 t 或 t' 都能取消分裂，取消只砍掉 t' | 「分裂实现起来很简单…取消分裂操作 只会把 t' 砍掉」 |
| N20 | t' 需要存在一张表里面 | 「t' 需要存在一张表里面」 |
| N21 | 先把代数做成完备的数学理论，再做成完整实现 | 「我们先把这个代数在新的地方实现出来吧」 |

## 三、本文件的使用方式

设计文档每写一条，就回到这里查 N1–N21：

- **有 N 编号对应** → 这条设计是被需求覆盖的，保留。
- **没有 N 编号对应** → 这条设计是「我加的」，要么删掉，要么在设计文档里单列一节说明为什么必须加。
