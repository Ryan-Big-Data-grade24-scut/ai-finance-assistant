# Ledger 引擎 V3.0 验收说明

> **历史版本说明：** 本文记录 V3.0 当时的验收口径。V3.1 已扩展部分退款处理，新的退款规则、黄金数值和验收命令以 [V3.1-引擎验收说明.md](V3.1-引擎验收说明.md) 为准。

## 1. 推荐验收方式（不会污染真实账单）

在项目根目录双击 `scripts/verify_ledger_engine.cmd`，或执行：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts\verify_ledger_engine.py
```

验收脚本只使用 `sample_data/支付宝格式_引擎验收_虚构数据.csv`，并在系统临时目录建立独立 SQLite 数据库。不会读写 `db/bills.db`，进程结束后临时数据库自动删除。

## 2. 测试账单覆盖范围

- 普通支出与普通收入
- 中性交易默认按支出处理
- 商品说明含“收益发放”的中性交易按收入处理
- 全额退款：原交易“成功退款（元）”金额等于原交易金额，并且退款行有同一商家订单号
- 孤立退款：找不到原交易引用时只把退款行置零，不猜测其他交易
- 部分退款：不自动当作全额退款，保留原交易金额并提示人工核对
- 自有账户内部转账：同一商家订单号、转账语义、方向相反、金额相等且有本人/自有账户标记才自动配对归零
- 外部额度交易：必须显式配置 `tx_overrides.funding='亲情卡'` 后才能 split
- split 产生等额反向镜像腿，并进入唯一 `external_income` 节点
- ADD/NET、undo/redo/unsplit、根净额审计
- 交易关闭行在导入时被过滤

## 3. 黄金结果

导入后、尚未 split 外部额度交易时：

| 指标 | 预期值 |
|---|---:|
| 有效交易笔数 | 13 |
| 支出 | 226.75 |
| 收入 | 201.20 |
| 净额（收入 - 支出） | -25.55 |
| 全额退款配对数 | 1 |
| 内部转账配对数 | 1 |
| I1–I6 不变量 | 6/6 通过 |
| 根净额审计链 | 通过 |

把 `T202609100010` 配置为亲情卡并执行 split 后：

| 指标 | 预期值 |
|---|---:|
| 支出 | 226.75 |
| 收入 | 321.20 |
| 净额 | 94.45 |
| 镜像腿 | 支出 0.00，收入 120.00 |
| I1–I6 不变量 | 6/6 通过 |
| 根净额审计链 | 通过 |

这里净额增加 120.00 是设计定义：split 把外部额度交易从单腿 `(120, 0)` 变成主腿 `(120, 0)` 加镜像腿 `(0, 120)`，并非金额计算错误。undo 应恢复 split 前结果，redo 应恢复 split 后结果，unsplit 应再次回到 split 前结果。

## 4. 手动在网页中测试

如果要在网页中导入 CSV 并查看星图，请先复制一份项目到单独的测试目录，确认测试目录中没有真实数据库，初始化空数据库后再导入测试 CSV。**不要为了验收把测试 CSV 导入正在使用的真实 `db/bills.db`。**

## 5. 设计边界

当前设计文档定义的是等额全额退款配对。部分退款尚无完整的腿级分配代数，所以系统明确提示并要求人工核对，不会把部分退款错误地静默归零。内部转账只对带明确订单关联键的记录自动配对；仅金额相同不足以认定为自有账户划转。
