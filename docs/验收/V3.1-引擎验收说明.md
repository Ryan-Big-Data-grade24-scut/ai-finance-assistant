# Ledger Engine V3.1 验收说明

## 本次升级范围

V3.1 在 V3.0 的 `ledger_legs` 持久化、唯一归属、I1–I6、M₀、Undo/Redo 和 MCP 基础上，集中完成：

- 全额退款、部分退款和多笔退款的统一识别。
- 通过显式原交易 ID、原订单号/交易号或平台共享订单标识建立退款关联。
- 平台累计“成功退款金额”优先；缺失时使用唯一关联退款流水合计。
- 退款流水自身生成零值腿，避免重复计入收入。
- 部分退款按 `原金额 - 累计已确认退款金额` 计算剩余有效金额。
- 退款超额、关联不唯一或累计金额冲突时输出警告，不猜测配对。
- 部分退款后仍涉及外部额度时，对剩余金额生成主腿和镜像腿。
- 全额退款、本人账户互转和退款证据冲突会解除或阻止分裂。
- 根净额审计拆分为中性定向、退款、内部转账、外部分裂四个阶段。
- 增加随机操作序列、退款关联、日期筛选、Live 导入后分裂同步等回归测试。

## 退款口径

例：原交易 100 元，累计确认退款 30 元：

- 原交易原始金额仍为 100 元，不修改 `transactions_raw`。
- 原交易有效金额为 70 元。
- 已关联退款流水生成零值腿，不额外增加收入。
- 若原交易使用外部额度且已分裂，则主腿和镜像腿都按剩余 70 元计算。

若退款金额超过原交易金额，系统不自动抵扣。若平台累计退款金额与已关联退款流水合计不一致，系统按平台累计金额计算剩余金额，但标记冲突并禁止该交易继续分裂，等待人工核对。

## 本地验收命令

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m backend.mcp.server --selftest
```

本次不新增数据库表，不要求修改 `schema.sql` 或执行新的数据迁移。

## 兼容性

- `transactions_raw` 保持不可变。
- `ledger_legs` 仍只保存 `(book_id, tx_id, node_id, role)` 结构，不保存金额。
- `ledger_placements` 继续作为已退役兼容表，不恢复为业务数据源。
- 退款金额由不可变原始交易与退款关联证据实时计算。
- 原有 AI 分类、MCP 工具协议和报告模块不改变。
