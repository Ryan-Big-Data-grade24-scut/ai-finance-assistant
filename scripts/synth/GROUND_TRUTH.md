# v3 标准答案与盲测口径

只把支付宝、微信、小荷包、银行卡、电商和投资目录里的原始账单交给受测方。`ground_truth/`、`verification/`、`backend/`、汇总和对账文件由出题方保管；它们含有跨渠道关系和未公开真值。

## 预算和资产是两套口径

| 项目 | 日常预算口径 |
|---|---|
| 收入 | 工资、年终奖、产品利息及派发收益 |
| 义务支出 | 房贷、车贷、消费贷、信用贷、既有信用卡分期、保险、物业、车位等 |
| 刚性支出 | 通勤、基础餐食、生鲜日用、医疗、教育、水电气宽带、理发、车辆保养等 |
| 弹性支出 | 聚餐、外卖加餐、咖啡、休闲购物、订阅、旅行、节庆礼品等；旅行车票不是通勤 |
| 单列现金流入 | 配偶共同出资、退回期初所属税年的预扣税款，不计账主本期所得 |
| 中性 | 自有账户划转、还卡/还花呗、投资申赎本金、关闭订单、支付镜像 |

月供在预算中含本金和利息；现金腿与本金余额各自对账。投资账户另报卖出实现损益和浮动损益，两者都不算日常预算收入。退款按**到账日**冲减原消费类，保留原消费日；退款不是收入。

- `ground_truth_periods.csv`：日、月、季、半年、年；`outflow` 为毛支出，`refunds` 为已到账退款，`net_outflow` 为净支出，`net` 为收入减净支出。三个支出类分别有毛额、退款和净额。`ANSWER.md` 是中文摘要。
- `ground_truth_actors.csv`、`ground_truth_accounts.csv`：主体、账户归属、期初/期末。`ground_truth_events.csv`、`ground_truth_legs.csv`、`ground_truth_state_changes.csv`：业务状态、现金路径、按事件发生的非现金状态变化。
- `ground_truth_postings.csv`：每行用 `event_id` 查业务、用 `tx_no` 查原流水、用 `source_exports` 查导出文件。`mirror_of` 关联支付主行；电商以订单号查证。基金/券商/收益/快照事实表也可回查事件；没有单号的以完整字段和重复次数核对。
- `reconciliation.csv` / `.json`：按源文件检查每行字段和重复/缺失。`verification/full_year/`：从期初重算现金、状态和退款路径。这两项验证回答不同问题，不可互相替代。

## 什么可以得分

`ground_truth_evidence.csv` 标注特定关系是否能根据这套文件核对。原字段直证与限定在可见字段下的唯一组合可以评分；多解、缺证不计为识别失败。配偶是谁、小荷包操作人是否是真正付款人、同额退款对应哪一原单，不因生成器知道就算原始流水可知。没有共享转账号的源不会硬添一个。

错分率只以支付宝有平台分类、微信有可比较消费类型的非镜像消费行作分母；不纳入转账、退款、订单副本。微信的类型字段不是细粒度消费分类，因此也单列支付宝的错分率。个体户被归入粗桶、字面关键词误判是刻意设计的；这些比例不用于估计真实平台的分类质量。

## 用现有导入器跑隔离账本

```bash
python -m scripts.synth --months 12 --seed 20261126 --backend
# 或对已有数据集补跑；输出必须是新目录或空目录
python -m scripts.synth.backend_ledger \
    --dataset ../synthetic-data/20261126-v3 \
    --out ../synthetic-data/20261126-v3/backend
```

`noisy.db` 保留平台预设分类，`truth.db` 用答案分类建树。现有导入器只覆盖支付宝、微信和小荷包；银行卡、信用卡、电商和投资不会被误称为已导入。`ledger_report.json` 列出覆盖文件、两本账的分类金额，并单列只在原付款及退款主行都入库时才能冲减的净额。该报告不代表 Ledger2 原生净额或全年全账户净额。生成器和隔离后端都拒绝覆盖非空输出目录，不打开正式账本。
