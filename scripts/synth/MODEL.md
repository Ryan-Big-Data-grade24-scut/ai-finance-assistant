# 虚构家庭交易模型（v3）

本文件是生成器的设计基线，不是真实用户数据。人物、账户、商户均为编造。

## 0. 先有交易，再有流水

日期和概率只产生业务指令。主体、合同、订单、实际出资账户与结算去向决定指令是否生效；平台分类、脱敏名称和交易单号只是凭证的展示字段。

| 交互 | 前置状态与资金来去 | 可见凭证 / 失败结果 |
|---|---|---|
| 雇主发薪或发奖金 | 雇佣条款产生待付款；雇主运营资金→本人银行账户 | 工资卡来款；雇主无款则待付，不能直接给工资卡加余额 |
| 商户或摊主卖货 | 订单或现场购买确认；付款账户→商户，平台代收时经平台清算账户 | 直接刷卡只出卡账；钱包绑卡同时出钱包和卡账；小荷包付款出支付宝和小荷包凭证；电商另有订单。镜像不是第二笔消费 |
| 家庭共同出资及代付 | 配偶自有资金→家庭钱包；亲属卡的消费发起人不是扣款账户所有人 | 不用小荷包操作人冒充付款人；共同出资不是个人工资 |
| 合同及账单扣款 | 服务方开账单或既有贷款待还；指定账户付款。本金还贷款账户，利息归贷款方；分期本金来自期初负债 | 银行、卡或钱包各见自己的凭证。余额不足留待付，不写成功扣款 |
| 账户调拨及信用结算 | 储蓄/钱包账户之间移动资金；刷卡/花呗由授信方垫付，产生债务；还款减少债务 | 双方单号可以不同，答案层关联；还款不重复算消费 |
| 退款 | 需有成功原单及未退款金额；商户/平台沿原结算路径退回实际扣款产品；信用退款可形成卡内溢缴款 | 渠道有原单/退款字段才展示；无字段不伪造；跨期按实际到账日冲减 |
| 投资 App 与产品方 | App 提交指令；认申购现金换份额，赎回按份额注销，净款归银行、手续费归收费方。券商现金换持仓；行情变动只影响估值 | 银行和产品凭证各见一侧，收益和现金到账、持仓和估值不可混用 |
| 税务机关 | 对声明的税年和可退预扣余额结算，由税务资金账户支付 | 银行现金流入，单列税款返还，不当成当期新增所得 |

模拟范围是家庭及直接交互方，不重建整间公司或市场。窗口前已存在的雇主/配偶资金、平台结算准备金、历史负债、税款与持仓必须登记期初；期初不是本期收入。无匿名无限余额账户。事件内资金腿要么全部生效，要么无一生效。

## 3. 生成分层

1. **合约层**：工资、月供、保险、学费、订阅，日期和金额确定。
2. **周期层**：每周采购、每月账单、每季物业，按日历锚点触发。
3. **随机层**：每日餐饮/交通/购物，泊松过程 + 类别分布 + 季节因子。
4. **事件层**：医疗、旅行、维修、人情、退款，低频冲击。
5. **结算层**：信用卡账单周期、花呗还款、转账配对、余额约束。

生成顺序：先生成事件日历，再展开成流水；不允许先生成流水再倒推规则。

## 5. 随机参数

- 笔数：工作日 Poisson(3.5)，周末 Poisson(5)，节假日 Poisson(7)。
- 类别权重：餐饮 35%、交通 15%、购物 20%、日用 10%、娱乐 8%、医疗 4%、其他 8%。
- 金额：按类别用对数正态分布，保留两位小数，偶发 `.90/.99`。
- 季节因子：1 月 +30%，6 月 +20%，7–8 月 +15%，11 月 +25%，12 月 +10%。
- 平台选择：支付宝 55%、微信 35%、直接刷卡 5%、其他 5%。
- 线上线下：线上 60%、线下 40%。

## 6. 结算约束

- 信用卡：账单日前的消费本期还，账单日后的下期还；全额还款为主。
- 花呗：1 日出账、10 日结算；资金不足不伪造还款，不模拟逾期罚息和新增分期。
- 小荷包付款可同时出现在支付宝主账与小荷包账；后一条是凭证镜像。
- 转账两侧独立编号；如有两侧投影，金额相等、时间差不超过 60 秒。`event_id` 仅在答案层共享，不用虚构商户号充当转账号。
- 退款关联成功原单，沿实际付款路径退回，累计退款不能超过原金额；信用退款可能形成溢缴款。
- 现金不能透支；余额宝/零钱通有 15,000/5,000 元的付款保留额。贷款用期初未偿本金和简化利率计息，不模拟真实催收、逾期、合同再融资或企业全套总账。
- 同种子、同生成版本、同依赖环境可复现账单和答案文件。后端 SQLite 有运行时元数据，不要求字节相同。
