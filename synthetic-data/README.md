# 虚构账单样例：生成方法

**先模拟交易，再导出流水。** 不先随机拼一行“某天花了多少钱”，而是先回答：谁因为什么，用哪个账户付给谁？钱从哪里来，最后到哪里去？

## 核心流程

1. **先定主体、账户和期初状态。** 定义家庭成员、雇主、商户和摊主、平台、银行、贷款方、投资产品方等。账户明确归属；期初现金、历史负债、持仓和可退税额事先登记。期初不算当期收入，余额不足也不凭空补钱。
2. **让日历和随机规则触发业务，不直接写流水。** 固定周期触发发薪、月供和账单；随机规则决定何时买什么、向谁买、用什么账户付。业务层检查合同、余额、授信和原单。结算要么整体生效，要么不动钱；未付或取消可以留状态，不能伪造成成功交易。
3. **记一次资金流，再生成各渠道的凭证。** 每笔结算记录现金从哪到哪；负债、份额和估值另外记。例如：支付宝绑卡买了 ¥120，发卡方垫付、商户收款、持卡人新增 ¥120 债务。支付宝和信用卡各有一行，但只算一次消费；还卡只清偿债务；退 ¥35 必须冲回原卡，而不是转进支付宝余额。
4. **把业务用途、平台标签和可见证据分开。** 答案按业务用途划分收入、义务、刚性、弹性；日、月、季、半年、年都保留毛支出、到账退款和净支出。原始格式有交易对方字段时，直接写在流水里。平台标签故意制造关键词误判，并把个体摊主压进通用类别；错分率只算可比较的消费主行。答案知道哪两行是同一笔，不代表受测方看得出来：原字段直证或可见字段能唯一匹配时才给这项关系评分，多解和缺证不算错。
5. **分别验证业务、余额和导出。** 手算关键场景，检查退款、卡账和申赎规则；从期初独立重放现金和非现金状态；读回原始 CSV/XLSX，逐行检查金额、字段及重复次数。同一代码版本、依赖、种子和区间在新目录重跑，比较原始导出及答案文件的 SHA-256。SQLite 不要求字节一致，单独用真实导入器验证支持的文件。

## 复现与取用

在仓库根目录，用项目虚拟环境运行（Git Bash）：

```bash
.venv/Scripts/python.exe -X utf8 -m scripts.synth \
  --start 2026-01-01 --months 12 --seed 20261126 \
  --out ../synthetic-data/20261126-v3-repro --backend
```

省略 `--out` 时默认写入仓库外的 `../synthetic-data/20261126-v3/`。输出目录必须不存在或为空；重跑换新目录。`--backend` 会用现有导入器和 Ledger2 建两本隔离账（平台分类、答案分类），只覆盖支付宝、微信和小荷包。银行卡、电商和投资等使用近似格式，不入库。去掉 `--backend` 仍可生成原始账单、答案和核验文件。

| 输出 | 用途 |
|---|---|
| 支付宝、微信、支付宝小荷包、银行卡、美团、淘宝天猫、京东、投资目录 | 原始凭证；盲测只发这些目录 |
| `ground_truth/ANSWER.md`、`ground_truth/ground_truth_periods.csv` | 简要答案、逐日/月/季/半年/年统计；只给出题方 |
| `ground_truth/` 下其他表、`reconciliation.csv`、`verification/` | 查事件及资金去向，验证原始行覆盖、状态重放与退款路径；只给出题方 |
| `backend/`（可选） | 两本隔离账及导入覆盖报告；只给出题方 |

本仓库发布文档、生成器和测试，不跟踪整套导出、运行日志或数据库。示例种子是公开的；正式盲测请换未公开的种子和输出目录，只发原始凭证。生成器只使用虚构资料，不读取真实账本。改生成规则时，先看[交易模型](../scripts/synth/MODEL.md)和[答案与评分口径](../scripts/synth/GROUND_TRUTH.md)，修改业务和结算规则，不在导出文件里修数字。
